# 变量布局与容器存在状态

2026-10-12，v0.8.1 布局。用户最终选择：无法无损表示父容器存在状态时保留完整 JSON，不增加结构辅助行，不另存一份异步结构状态。

## 当前实现

新转换为每个已映射的顶层变量保存一个完整 JSON 单元格，包括对象、字典、数组和标量。开放的 stat_data 根仍整体映射为一张完整根表。未映射的脚本根数据继续使用原消息变量；没有新增全局动态兜底表。

空单元格表示整个变量缺失，JSON `null` 表示空值，`{}` / `[]` 表示空容器。唯一身份行保留，变量增删通过单元格或内部 JSON 路径操作。每个业务值只有一个存储位置，不再重复保存到扩展列或派生表。

这次没有恢复草案中的字典行表。局部复杂节点并不必然要求合并无关兄弟节点；但任意作者完整替换可以省略整个已映射根变量，普通列和零行业务表不能完整区分缺失、空对象以及原值。当前最小可靠边界因此上移到已映射根变量。标量也须能够表达缺失，不能在读回时补出旧初值。

普通列、行表和关系表仍可作为未来候选，以及既有转换卡的兼容布局。旧卡与旧聊天不自动改布局。不得把保留的旧布局读写测试当成新转换仍生成这些布局的证明。

## 原行为证据

MVU 原生更新拒绝删除 required 字段；原 Zod 链拒绝删除必填字段，可选容器可以缺失，default 可能恢复默认值。删除最后一条字典记录通常留下 `{}`。这些行为沿用原实现，不由转换器重新猜测。

原 Mvu.replaceMvuData 直接调用酒馆助手 replaceVariables，该直接替换入口不自动执行登记的 Zod。因此正常模型更新的必填约束不能证明作者完整替换永远保留字段；也不能把缺失静默改成空对象。

消息变量可以放结构信息，但数据库公开 SQL 更新回调位于提交和保存之后。现有公开接口不足以将结构标识与所有模型 SQL、CRUD、清空和回放路径原子同步。数据库内部的提交前钩子不等于外部可用接口。用户未授权新增此类数据库 PR，本轮不接入事后补存方案，也不按最终零行猜测 SQL 曾做过哪些操作。

## 数据与说明

保留原变量路径、实际 JSON 类型、数组顺序、重复值、字面键和对象归属。内部 `$` 数据随所属对象保存和删除，默认发送投影递归过滤；展示隐藏不是硬写锁，已声明隐藏字段仍有写入位置。作者业务规则与原 Schema 保留，不按自然语言猜测维护者。

DDL 默认值不复制完整初值。说明只保留必要的容器定位、编码、SQL 操作与作者原文；移除转换器生成的旧“内部数据，AI 不应直接修改”说明。内部路径字符串使用 SQL 字符串；整列 JSON 字符串使用 json_quote。未知变换输出不按初值猜类型。

## 验证边界

公开当前转换矩阵经实际 writer、codec 和状态导出检查缺失、null、空容器、恢复、嵌套隐藏归属与标量类型。最小隔离 SQLite 宿主验证模型 SQL、脚本完整替换、净零更新及刷新持久化。十五张开发卡使用固定远程源码检查初始完整读回；这不等于穷尽所有分支或证明真实模型游玩质量。

旧布局夹具使用已知构建基线冻结的公开合成输入输出，经当前产品读写实现测试。捕获时立即深拷贝，使用保留 undefined 和集合的编码；不依赖本地旧源码运行公开回归，私有参考卡不进入公开夹具。
