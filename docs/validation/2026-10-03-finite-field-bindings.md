# v0.4.5：有限字段绑定与复杂声明路径

## 根因与契约

本批由复杂本地角色卡触发，公开回归均使用独立合成数据。原卡正文、脚本与完整产物不提交。
主角表在 v0.4.3 前、v0.4.3 和 v0.4.4 中均被识别为 19 行字典表；本次发现的是既有缺陷，不能归因于 v0.4.3 新引入。

| 已证问题 | 根因 | 通用修复 |
| --- | --- | --- |
| 固定字段变成条目行，子字段被提升到父表 | `${字段}` 不区分有限绑定和未知条目键；对象 type 的归属依赖大括号文本猜测 | 同节点字符串枚举/列表展开有限字段名；类型属于其声明字段，保留固定身份 |
| 深层字典在父目录凭空出现 | 嵌套动态字段按简称登记到所属组 | YAML 类型和动态路径按完整逻辑路径登记、读取，Zod 和显式 MVU 元数据保持原有优先级 |
| 二元素数组被读成值与说明 | 初值 pair 形状优先于数组声明；关系行编码也使用同一形状猜测 | `Array<T>`/`T[]` 的完整路径优先，未声明的旧式 pair 保持原契约 |
| 固定容器下数组改动未落表，多层关系串位 | 写入规划仅检查 `writePaths`，遗漏数组布局 `path`；固定根记录带入不存在的祖先键 | 所属判断包含数组路径；关联键只包含真实条目祖先 |
| 开放字典值被补造「描述」字段 | 将记录值内部的动态字段误当作一组固定业务列 | 记录值为开放字典、宽对象或数组时，以身份列加完整 JSON 内容列保存 |
| 旧前端的空值回退被空列挡住 | 展示扫描将 `旧字段 ?? 新字段` 中不存在的旧字段物化为默认空列 | 记录仅用于空值回退的读取；有明确结构声明且初值未出现的回退字段不补列，普通展示补列及运行期新增字段仍保留 |
| 输出条目夹带的数据约束被删除 | 旧输出条目按专名整体删除，静态规则覆盖只检查 check/note | 从可解析输出文档中分离 format；未知规则保留为独立数据约束，只有完整已知协议定义可删除；EJS/无法安全分离的混合文档保留 |
| Schema 返回值中的初始物理行号重复 | 两个行表构造分支使用列数而非行序号 | 每张表独立连续编号；同时检查 Schema 返回值和生成模板。模板生成原先另有归一化，不能把这项修复直接当作宿主初始化失败的解释 |
| 带业务 ID 的表被宿主拒绝初始化 | 宿主将 `ID`、`rowid`、`row-id`、`row_id`、`行号` 当作系统身份列；原列名去重仅预留 row_id | 业务显示列避开全部身份别名，并同步本表键与跨表关联；逻辑路径及原始数据保持一致。实机警告证明原表在第 1 列出现第二身份列 |

有限展开设 64 个组合上限；绑定说明不成为业务子字段。未绑定占位符、索引签名和显式开放元数据继续按动态记录转换。没有针对卡名、角色名或资源名称的分支。

## 公开复现与本地数据检查

`test/bound-template-fields.js` 覆盖固定同形字段、点路径绑定、未绑定动态键、显式开放元数据、嵌套同名记录、数组/pair、开放记录值、前端回退、初始行号及业务身份别名。
`test/output-business-rules.js` 覆盖中文业务条件、英文空值/信息保真条件、纯协议、未知关键词、EJS 和混合格式。
`test/bound-fields-host.js` 的 Node 预检检查 7 张合成表；实机入口为 `node test/real-host.js --only=bound-fields`。

本地卡检查全部初始顶层组；修复后 31 表的初始化读回逐字段一致。按声明填充空记录并新增、更新多层同名记录，检查真实产品规划器的 API 载荷和读回值；在 SQLite 3.50.4 中执行全部 DDL 并插入 97 行，读回逐字段一致，数值字符串读回也一致。
这些 SQLite/模拟 CRUD 证据不等同于完整宿主保存与重载。

提示冻结只更新 `relationships/{native,sqlite,both}/split/static` 三项：完整 YAML 路径恢复独立的效果关系表，旧 JSON 效果列不再与新子表重复。其他 30 项摘要保持原值，浏览器无 require 装配一起验证。

## 规则与脚本边界

主规则 141 条 check/note 均保留，其中 12 条发生既有用户/变量提示宏转换。输出文档中的空值禁止和信息保真条件已保留，旧格式块已移除。
原有 11 条正则全部保留；5 个业务脚本保留，MVU 引擎与纯外部结构启动器移除；3 个远程页面已有加载守卫。

卡内外部 import 无正文，静态转换不能恢复其任意默认值、校验、派生计算和事件逻辑。4 个远程业务模块未核验；2 处动态 EJS 无法安全静态改写，转换报告保留人工核对项。本批不声称这些远程模块已在真实运行中验证。

结构修复需重新转换原卡并以新模板建立聊天；旧转换卡、旧模板和旧聊天不自动迁移。
