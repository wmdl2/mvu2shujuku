# VWD 动态说明：固定模板、动态数据

本批接通单例表中已登记 `pair` / `jsonPairOptional` 字段的动态说明。说明随表格数据保存，
实际填表时从当前表格读取，不再要求 SP 修改 `sourceData.note`。原 MVU 更新模式和 Zod
提交前宿主接口按用户决定暂缓，本批没有修改这两条路线。

## 使用与范围

- 插件转换界面在 EJS 上下文桥就绪时自动传入 `vwdDescriptions: true`；目标 SP 须支持隐藏
  物理列（9.2.5+）。Node 核心显式传此选项才登记。旧 `vwdExperimental` 开关保留给旧实验
  回归，仍为 false；它不是新路径的总开关。
- 每张合格单例表增加一列隐藏元数据。模型看到实际列名、说明和业务规则，不需要理解该列。
  数字/布尔已标量化字段、动态行、数组元素、对象值 VWD 和旧布局自动迁移不在本批范围。
- 新转换卡支持值和说明同批修改、只改说明、同文不同字段分别更新、初始空说明事后补充、
  显式空串、恢复静态默认、刷新及删楼回退。原始说明在存储和 `Mvu.getMvuData()` 中保持原文。
- 保持提示词模板扩展启用。转换时缺少依赖则保留静态路径；动态布局运行时缺少 EJS 桥或
  匹配模板时拒绝说明写入。宿主跳过 EJS、捕获模板异常后继续请求的行为不受全局拦截；本批
  没有包装 fetch，也没有承诺依赖扩展停用后仍可正确渲染。
- 验收针对当前聊天的普通填表请求；任意历史批量填表上下文尚未纳入保证。既有旧卡/聊天
  不改写，使用新能力需要重新转换并在新聊天中验证。

## 实现

`buildSchema` 按转换选项登记新布局，`vwd.promptVersion: 1` 区分请求时渲染协议。每个字段
用登记路径数组的 JSON 串标识，沿用隐藏覆盖集合与逐字段插槽。初始空说明也保留插槽。

`buildVwdPromptNote` 只替换字段说明位置：每张表一段 EJS 前导读取本表所有说明，原业务
规则、宏、列名和 SQL 示例保留。`plan` 保存插槽；`noteTemplate` 保存规则/宏迁移后的完整
固定模板，用于运行期匹配。默认说明中的宏仍按布局规则解析，业务规则宏在提示管线执行。
不把全部 note 转义，也不按相同旧文本全局替换。

`mvu2shujukuVwdDescriptions` 从 SP 当前表格读取说明，不使用待写 overlay、不重建完整
`stat_data`，也不长期缓存某次生成的数据。普通文字原样输出；含 `<>{}$&`、控制字符等的
文本使用带说明的 JSON 字符串，相关字符编码为 Unicode 转义，防止 EJS、酒馆宏、SP 查询、
条件和随机模板再次解释。该表示是可逆编码，不能把它称为任意特殊文本“逐字符直接展示”。

writer 和候选工厂检查布局、元数据列、固定模板及 EJS 桥是否匹配。旧静态实验布局继续拒绝
说明变化；新布局的原始 pair 交给真实 writer 编码，不在候选构造时丢掉第二项。值和说明
沿既有批次管线提交，单行用 `updateRow`，多步依原有一次导入保证；不另发 note 同步请求。
纯值修改保留已有说明覆盖，说明未变不写元数据。

在转换器中编辑模板时，若动态入口和全部插槽仍完整，则同步更新产物内的模板基线并保留
原规则修改；破坏动态入口会产生报告警告，运行时拒绝说明变化。普通静态转换继续复用原
schema 引用；没有为新功能破坏参数编辑的缓存契约。

## 同批修复：成功写入后的旧读窗口

短聊天探针复现：SP 物理表和新楼历史帧已有新值，但 `Mvu.getMvuData()` 仍返回旧值。
根因为插件的 `frontendCommittedMvuRead` 可保留上一次提交 5 秒；自有写入期间抑制 SP 回调，
没有刷新该窗口。不是宿主没有保存。

修复在成功写入、会话校验完成后，复用已经生成的 `afterMvu` 更新读窗口，再发事件。
不增加数据库调用或模型请求；缓存为了隔离监听器修改，会增加一次 JSON 克隆，成本随快照
大小变化，不能称为零 CPU/内存开销。拒绝、未完成和无变化写入不发布新缓存。

真实装配回归在修复前稳定得到“物理值 37、立即 getter 为 10”，修复后成功 Promise 后立即
读到 37。实机断言也保留立即读取，不靠等待 5 秒来掩盖问题。

## 提示与计算成本

`node test/measure-vwd-prompts.js` 使用公开合成卡及 `o200k_base`，只比较说明片段：

| 样本 | 原始 tokens | 新表示 tokens |
| --- | ---: | ---: |
| 合成卡好感系统整张表的 note（原有两个同文说明、一个空说明） | 117 | 122 |
| 普通说明“完成委托后提高好感上限” | 9 | 9 |
| 含 EJS、酒馆宏和 SQL 查询标记的特殊说明 | 32 | 67 |

整表样本增加 5 tokens，主要来自空说明字段的位置。特殊文本编码有额外成本，换取保留原文
信息且不执行其中标记；没有统一的节省比例。模板内的程序代码和隐藏元数据不进入正常模型
请求，也不增加模型调用。真实模型对说明的理解质量仍由实际使用观察。

此次测试中，三字段说明的纯 codec 处理约 0.003 ms/表（10,000 次循环预热后），包含模板/插槽检查；
不含 SP 导出、保存、网络，也不含上面读缓存克隆的整批成本，不能外推成完整填表耗时。
