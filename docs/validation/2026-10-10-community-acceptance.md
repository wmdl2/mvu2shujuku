## 新发现与修复

前一 `7e22c6d4…` 的第 08 张写入及重载一致，但填表 JSON 数据视图实际读取失败。数据库受测版本 `prompt-api-call.ts` 用字符串 `replace('$0', tableDataText)`，生成 SQL 中的美元符号紧邻单引号会触发 JavaScript 的替换后缀语义，破坏内部 SQL 宏。固定响应仍能写入，旧检查漏掉了模型根本看不到当前 JSON 行的问题。

产品 `stat-storage.sendRowsSql` 改用 SQLite `char(36)` 做同值比较。续验第 06 张发现 DDL 中的 JSON 根路径仍触发同一替换语义；现在 DDL 的默认值、枚举、JSON 路径与操作示例共用 `sqlTextLiteral`，危险美元符号生成等值 SQLite 字符串表达式，普通字面量不变。没有另写 SQL 解析器或修改数据库源码。公开回归通过实际产品生成的模板、宿主同类字符串替换边界及 SQLite 查询验证。新增实机检查核对最终请求中的当前数据行，而非仅检查表名和写回值。

消息变量适配另发现原生存储遗漏：酒馆助手的 `replaceVariables` 替换整份消息变量对象，旧适配在委派普通变量更新时删除了整块 `stat_data`，导致独立隐藏状态被提前清空。现委派时带回当前原消息状态，实际目标变更仍走数据库提交和回滚。新增两项公开回归在修复前均复现丢失，修复后连同相关原消息场景 7/0。普通辅助变量与数据库更新不构成跨存储事务。

私有夹具同时修正两处前置条件：世界书导入不再依赖 `importEmbeddedWorldInfo` 从 DOM 取得的角色编号，而是对明确卡数据调用同一宿主转换、保存和列表刷新接口并核对条目数；数据视图检查按真实 JSON 列编码处理空单元格，不能把键缺失的空值当成非空 JSON。
