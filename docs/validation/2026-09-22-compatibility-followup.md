# 通用兼容补齐：规则、旧楼提交与数值说明

本批基线为 462 项已通过回归。未重开历史审查；本批只处理以下三个已定位行为。

## 行为变化

### 嵌套 YAML 占位规则

`记录 → ${名称} → 数量 → check` 与已有点路径规则得到同样的字段登记。
支持独立 `${…}`、`<…>`、`*` 占位键，保留集合说明、子字段检查、格式、范围、小枚举与备选键。
扫描不会将 check/note 正文里的点号当成路径；循环 YAML 引用停止递归。
新回归位于 `test/nested-wildcard-rules.js`，也检查实际生成的表格说明。

### 较早楼层的业务修正

SP 已保存的提交触发业务监听器后，较早楼层的修正先在内存运行真实 writer，
再检查来源及原表是否变化。只需一次 CRUD 的修正照常提交；同行多个字段可合为一次 updateRow。
多次 CRUD 或需要整表导入的修正，在第一次真实写入前整笔拒绝。单次更新被拒绝后不拆分补写。

这修复了“先改一部分再失败”的插件行为，**不是**增加了任意旧楼事务能力。
公开导入选择最新 AI 楼，不能拿它冒充指定旧楼提交；SP 已经保存的原始操作也不会被该守卫撤销。
缺少指定旧楼的整体提交接口时，多步业务修正仍不支持。

### 数字与布尔 pair 的动态说明

新 `vwdDescriptions: true` 布局将单例中带 pair 标记的 number/boolean 字段加入说明登记。
物理列仍保存数字和 0/1；读回恢复 `[当前值, 当前说明]`，说明仍使用已有隐藏覆盖列和固定 note。
支持说明单独变化、清空及恢复默认，SQLite 返回数字字符串时也保持逻辑类型。
Node 默认静态转换与旧实验布局保持原标量形状；未登记普通数组不拆包。
动态行、数组元素和对象值 VWD 尚未在此批扩展。
