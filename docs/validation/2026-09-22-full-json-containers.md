# 完整 JSON 容器转换

用户在了解隐藏状态表仍会向模型显示名称/row_id 后，选择完整 JSON。
本批复用已验收的 `jsonObjectOptional`、候选工厂与运行时写入入口，没有新增状态表或状态列。

## 使用与范围

转换界面新增「将容器保存为完整 JSON」选项，需在重新转换前勾选。
Node 调用为 `core.convert(card, { jsonContainers: true })`；也可传顶层组名数组，
例如 `{ jsonContainers: ['档案', '背包'] }`。未选择此选项时保留原表格映射。

被选中的已有顶层对象/数组各用一张表、一列「内容」保存；原来的相关子表合并进去。
标量和 MVU 保留元数据组不被该选项改写。已声明可空的完整 JSON 组复用既有实现。
既有卡及聊天不会自动改布局，需使用新转换卡建立新聊天。

- 空单元格：该顶层变量不存在；`null`：明确空值；`{}` / `[]`：空容器。
- 内部记录删除、null、空对象，以及数组元素和对象值中的 `[当前值, 说明]` 原样保存。
- 说明直接包含在当前 JSON 数据中，既不复制到隐藏覆盖列，也不要求 EJS 动态说明入口。
- SQLite 支持 JSON 路径局部修改；native 填表需要提交整个 JSON 单元格。此处推荐 SQLite。

这是一个完整容器的兼容入口，不表示旧拆分布局中的任意 VWD 或空状态也自动获得新能力。
不存在于初始数据或结构登记中的任意新顶层组、旧聊天迁移和任意 Zod 语义等价不在本批承诺内。

## 实现与规则

`schema-layout.js:preserveJsonContainers` 在原有规则推导后，按布局中的完整路径合并属于同一容器的表。
复用字段说明、业务条件、格式、范围、枚举与动态路径规则，不保留已经失效的父子表定位指令。
pair 的当前说明以 JSON 第二项为准，静态 note 不再重复它的初始说明。

固定路径约束继续进入 JSON CHECK；数字 pair 的值路径用数组下标 `[0]`，
字符串键 `"0"` 仍是对象键。动态键/任意数组元素的限制保留在说明并明确告知无法用 CHECK 遍历验证。
内部 `_` 字段继续由已有提示标明只读。混合 JSON 的深层 `$` 字段不能单独隐藏，沿用已有报告警告；
选择此模式前应检查含私有数据容器的转换报告，不能宣称仍有逐物理列隐藏效果。

## 成本与默认值

原 MVU 数据中的完整 JSON 本身不是转换器新增的数据；但表格包装、规则和默认值仍可能造成额外重复。
本批计量发现大 JSON 被复制进 DDL DEFAULT，已将新模式的 SQL 默认改为空单元格，
初始数据继续保存在 content/seedRows 和布局默认值中；不改变初始化数据。
隐式复用模板的刷新若切换 jsonContainers，会重新生成对应列，防止新布局套上旧模板。
未把静态模板库存当成完整模型请求，也未用固定响应推断真实模型质量。

计量脚本 `test/measure-json-containers.js` 使用公开合成样本、`o200k_base`，分别列出可见表格数据、
note、DDL 和操作说明；这些字段不一定在同一次请求里全部出现。原始 stat_data 计数不含 MVU 规则及外围提示。

同一公开输入的最终库存（token）：

| 记录数 | 表示 | 表数 | 可见 content JSON | note | 可见 DDL | 操作说明 |
| --- | --- | --- | --- | --- | --- | --- |
| 2 | 原表格映射 | 3 | 104 | 475 | 145 | 289 |
| 2 | 完整 JSON | 2 | 89 | 804 | 128 | 132 |
| 200 | 原表格映射 | 3 | 7034 | 475 | 145 | 289 |
| 200 | 完整 JSON | 2 | 6227 | 804 | 128 | 132 |

200 条样本的完整 JSON DDL 优化前为 5333 token，优化后 128；消除的是初值重复。
JSON 路径/空状态指导使 note 增加，因此不能声称所有小卡都更省。表格模式与完整 JSON 的
说明表示及原始类型保真范围也不同，库存对照不证明真实模型质量相同。原始紧凑 stat_data
JSON 分别为 62 / 5210 token，不含 MVU 更新规则，不能当作原 MVU 完整请求成本。
