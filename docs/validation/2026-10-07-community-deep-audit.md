## 已确认并修复：不同开场字段的物理表名冲突

一些卡的旧开场使用不带符号的字段，当前 Schema 和新开场使用 `$` 或 `_` 开头的字段。原始 JSON 路径与项结构不同，但第4张卡的作者 Schema 明确将旧机遇字段归一到新字段并删除旧名；完整 Schema 对旧开场验证成功，2条机遇得以保留。转换器为多开场预建存储位置，因此会保留两种字段身份；各开场保留独立的数据快照，缺失组不会被补成另一份数据。

数据库根据显示名生成物理名称，去除符号后可能同名；它不使用转换器 DDL 的旧标识符来消除该冲突。原实现只检查显示名的字面重复，遗漏了宿主身份规则。

用户批准只给后续冲突表追加编号，保留变量路径并写报告。修复以受测宿主锁定的 pinyin-pro@3.28.2 和算法 v1 检查顶层及嵌套派生表，覆盖符号、大小写、同音与截断；超长冲突只缩短显示名的必要尾部，使编号进入宿主截断范围。初值、逻辑路径和作者脚本不被合并或改名。

公开回归 `test/sheet-identity.js` 覆盖双模式、不同分支结构、顶层/派生冲突、截断和不依赖 Node 作用域的内联工厂。两个原卡的真实宿主初始化也通过。

## 已确认并修复：直接世界书函数缺少别名适配

在同一已完成初始化的作者脚本窗口中，`getWorldbook(旧书名)` 失败，但 `TavernHelper.getWorldbook(旧书名)` 成功。其他窗口正常，说明不能仅根据启动日志将其归为时序问题。

运行时现在让已有的直接世界书读写及名称查询函数复用 `card-api.js:facade`，通过 `runtime-globals` 登记与还原。保留原接收者，不创建原本不存在的函数；过期写入拒绝，切卡恢复原属性描述符，也不覆盖其他插件的后续接管。公开测试覆盖实际共用工厂及内联 VM。

## 已确认的数据库侧问题：背景注入破坏 EJS

两张卡的原卡及转换后世界书均能单独编译，启用条目拼接也能编译；实际填表请求中的背景却编译失败并回退成原始 EJS。

受测数据库 `prompt-api-call.ts` 使用 `finalContent.replace('$4', worldbookContent)` 等字符串替换。替换内容中的 `$'`、`$&` 等具有 JavaScript 特殊含义，会改动原本有效的代码。相同冻结世界书通过原字符串替换可复现编译失败，改用回调替换后可以编译；原卡也受影响。此项记录为上游问题，没有改数据库参考库或篡改作者脚本来绕过。

## 已实现：按完整更新段落迁移旧协议

用户确认整段迁移方案，放弃逐句自然语言句式匹配。明确更新字段或纯更新条目作为迁移单位，条件、续行和结构化目标变化完整保留；指针绑定实际表列，改写旧输出协议后交给填表模型。已有表格说明原位改写，混合世界书拆为正文和填表两个视图，不向两处重复写同一规则。

结构化操作列表保留 add/remove/replace 等目标变化及数据，并提供局部表列映射和“不是输出格式”的说明。精确引用的业务字面值可保留，不宣称所有 JSONPatch 字符串都应删除。标签跨界、无法绑定的路径、YAML 共享节点、示例或正文段落、不能确认为只读的 EJS 保守保留；明确报告迁移未完成。

支持拆分的 EJS 保留条件和依赖，两视图分别加块作用域；这修复了拆分条目合并后 const 声明冲突。检查拒绝赋值、重绑定、删除、未知调用或宿主依赖，不将任意 JavaScript 自动视为只读。公开回归经过生产转换及工厂 VM，覆盖分流、完整操作数组、字面值、条件续行、关联路径、记录内容 JSON 绑定和安全回退。
