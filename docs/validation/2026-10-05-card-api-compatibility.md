# 注册 Schema、创角档案与世界书兼容修复

v0.4.11 修复了[3.2 MVU 卡基线检查](2026-10-05-card-32-conversion-audit.md)确认的四类缺口，并补齐实际本地路径钩子的括号路径。修复按通用协议实现，没有角色名或私人卡正文特例。

## 修复行为

| 路径 | 当前行为 |
| --- | --- |
| Schema 前存在正则、模板、辅助函数 | 按 JavaScript 字面量边界定位声明，展开支持的静态辅助函数；不执行卡内代码 |
| 已注册根组没有初值、联合类型无法静态展开 | 建立可表达缺失值的完整 JSON 存储；未知联合记录保留空字典及完整内容 |
| 新增根组不在布局中 | 提交前拒绝，并返回未映射组；不能以已计划部分成功冒充完整保存 |
| 本地命名导入并调用 registerMvuSchema | 保留脚本并登记实际 Schema，候选数据先校验、变换，再落表；未登记、失败、切会话则停止 |
| 本地路径规范化监听 | 接入真实命令的专属阶段；支持 JSON 引号括号路径，键内点号和斜线保留 |
| 已校验候选进入保存 | 会话、Schema 登记、完整数据一致时复用内部凭证，避免同一结果重复 transform；改值后重新校验 |
| 已知 NLKASHEI/MagVarUpdate 分叉引擎 | 转换时移除，避免外部旧引擎重新覆盖桥 |
| 原绑定世界书名 | 当前转换卡的助手外观将其路由到转换书；其他世界书保留原行为 |
| 助手创建单条 data.stat_data 档案 | 创建前校验，创建后等待数据库和该楼快照保存；失败抛错，多档案批次明确拒绝 |

外部旧 Zod 工具的专用事件继续使用隔离副本，防止再应用一次命令。无导入的纯结构声明仍作为静态参考后移除；纯外部 Schema 没有本地正文时仍报告人工检查。普通卡恢复原助手入口；无 Schema 卡不等待 Schema 登记，原开场恢复流程保留。

公开回归在 `test/card-api-compatibility.js`，使用真实工厂和组装运行时，覆盖解析边界、缺失根组、完整 JSON 读写、未映射失败、Schema 失败和异步切会话、世界书路由、档案创建失败、接口恢复、括号字面键及非幂等变换。

- 最终全量 658 项全部通过。此前 657 项的两项失败已修正，14 项补测覆盖旧开场恢复、显示视图及切会话；新增未知联合嵌套类型矩阵也纳入最终全量。未将中止的中间回归或 Python 沙箱失败算作通过。
- 固定 SillyTavern 1.18.0、龙血玄黄·数据库 1.2.4（`9bb5b242234819073b2ff13b4baa32741751e3dd`）、酒馆助手 4.11.3（`87ca341a2a2279f4c18cd1918c5ae9dbd1dac492`）。入口 `test/real-host.js --only=card-api` 验证 native 和实际 SQLite：解析后只变换一次、世界书路由、创角消息变量与数据库帧、重载、未映射组拒绝且表格不变。SQLite 检查实际生效模式，不把回退算通过。
- 指定卡转换后 52 表，原初始化 25 根组的已有值保留，并补齐静态可识别的声明默认值；实际 Zod 归一化结果的缺失组和同组数据差异均为空，创角所测组合原先缺失的 8 根组可写回。实际原 Schema 及 Zod 工具接入组装运行时后，属性更新计算得到生命上限／当前生命 125、士气上限 120；档案测试值进入真实助手消息变量和模拟数据库帧。这部分是组件对照，不是整张私人卡完整宿主验收。

宿主夹具明确启用角色级助手脚本，并导入转换世界书。单个脚本 enabled 为 true 不能证明助手会运行它。宿主使用受控注册模块和真实 Zod、助手及数据库；私人卡外部依赖使用冻结源码对照，不声称其远端未来版本等价。

## 使用与边界

更新扩展后重新转换原卡及配套模板，使用新聊天。保留并开启原 Schema 脚本和酒馆助手对该角色的脚本功能；网络资源加载失败或关闭脚本会阻止依赖 Schema 的写入。旧转换布局和已有聊天不会自动迁移。

动态新增未声明根组需要补模板并重新转换；未知外部 Schema、任意 JavaScript 副作用、每条命令中间状态及所有第三方辅助脚本不保证等价。数据库自身填表直接写入不自动经过 Mvu 候选校验。档案消息创建成功而数据库保存失败时消息仍在，需要检查错误后重试，不自动删除用户消息。动态 Schema 提供函数不复用校验凭证。

尚未验收正式 Android TauriTavern/WebView、真实模型完整游戏过程或这张卡全部选项组合；此前安卓发送跳楼、EJS 与 DOM 虚拟化的独立问题不属于本次已修复范围。
