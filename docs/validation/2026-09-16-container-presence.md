# 顶层可空容器：缺失、null 与空容器

实施始于 2026-09-16，2026-09-21 继续完成运行时接入与验收。

本批处理已静态识别的顶层 Zod 对象、数组和字典上的 nullable / optional / nullish 声明。
原来按字段或记录拆开后，整组缺失与空对象无法可靠区分，整组 null 被拒绝。
新转换把这类组保留为单例表的一列 JSON；普通组继续使用原布局。

## 存储与模型操作

| 内容单元格 | MVU 读回 |
| --- | --- |
| 空字符串 | 省略该顶层键 |
| 文本 `null` | 该键值为 null |
| 文本 `{}` / `[]` | 空对象 / 空数组，按声明种类选择 |
| 合法对象 / 数组 JSON | 原始容器值 |

不增加隐藏状态列。单例布局的 `valueCol` 指明该列直接投影到整个组；它不是名为“内容”的
业务子字段。列沿用 `jsonObjectOptional` 编解码和容器种类检查。声明初始缺失也生成表，
但不虚构初值；缺表加载窗口使用登记初值，有表而内容为空时保持缺失。

模型沿用同一表示，状态切换只更新单元格，禁止删除身份行。SQL 可用 JSON 路径局部修改；
native 需要完整的新单元格 JSON。内部字段名、类型、描述、范围、枚举和已识别业务检查规则
保留在 note，路径从内容内部开始。脚本写入沿既有 writer / 候选工厂 / 批次提交路径，
错误容器及不可序列化值在宿主调用前拒绝。

`Mvu.replaceMvuData` 接收完整目标快照。新完整容器组从该快照中省略，表示删除；修改其他
字段时先读取完整基线再提交。实机曾发现旧的“补回遗漏组”保护吞掉删除意图，已增加真实
运行时回归复现并修正，仅对登记完整容器投影的组生效；普通旧布局的补组保护不变。

固定字段路径上的范围和小枚举继续生成 SQLite CHECK；空值、缺失及原有初始哨兵值放行。
CHECK 可沿用现有设置关闭。动态键和数组内部元素的约束不能使用 SQLite CHECK 遍历，
保留规则说明并在转换报告告知；这不等于执行完整 Zod 校验。根 stat_data 仍要求对象。

## 范围与代价

- 只对上述明确声明的顶层容器启用，不迁移旧卡/旧聊天，不从旧空单元格猜测历史意图。
- 非可空字典中“某一条记录可空”、未声明但运行时变空的拆分组，仍需后续批次处理。
- 本批没有扩展 VWD 动态说明范围，也没有改变历史楼层多步提交语义。
- 无新增模型调用或宿主接口依赖。完整 JSON 减少结构歧义，但 native 写入大容器需要完整
  单元格内容；SQL 路径更新可减少修改文本。没有实测整请求 token，不宣称节省比例。
- 带私有叶子的整个 JSON 仍沿用既有可见性边界，不声称隐藏混合容器内部的私有内容。
