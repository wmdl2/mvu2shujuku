## 上游契约与边界

- SP 的 native 模式隐藏 SQL getter；CRUD readiness 不能用 SQL API 是否出现判断。
- SP 9.2.5 `table-history.ts:getLatestTableAppendMessageIndexFromChat_ACU` 为手动 CRUD 选择最近已有表帧的 AI 楼。消息更新使用 `importTableAsJson`，由 `table-import-service.ts` 选择最新 AI 楼并严格保存，保留删除／重生成的回退边界。
- 多步数组修改与消息快照导入失败时不会反向覆盖旧快照：上游可能已完成持久化，仅运行时恢复失败。
- 酒馆助手 `deleteChatMessages` 默认 `refresh: 'affected'` 不发送宿主 `MESSAGE_DELETED`。验收使用真实 `/cut`；自定义脚本静默改动聊天后，需要通过宿主事件或完整重载触发数据库回放。
- 本记录只覆盖公开合成卡及列明场景，不代表所有第三方动态前端、外部脚本和私有 MVU 内部接口都等价兼容。

## 复现

需要 Node 22，以及工作区参考目录中已安装依赖的 SillyTavern、酒馆助手、提示词模板、SP Git 仓库和 Playwright 浏览器。上游目录用途与恢复方式见工作区 `参考资料/README.md`。

```sh
node test/real-host.js
# 调试单一阶段；已有 state.json 时复用此前导入的公开测试卡：
node test/real-host.js --only=history
node test/real-host.js --only=regenerate
node test/real-host.js --only=ui
node test/real-host.js --only=sqlite
# 若已按相同 dataRoot / configPath 启动专用测试服务器：
node test/real-host.js --reuse-server --only=sqlite
```

可配置 `MVU_REFERENCE_ROOT`、`MVU_HOST_TEST_DIR`、`MVU_HOST_TEST_PORT` 与 `MVU_SP_TEST_COMMIT`。默认数据、截图与日志写入被忽略的 `.tools/real-host/`；脚本启动并关闭自己的服务器，不连接日常酒馆实例。端口被占用时直接失败。固定生成响应只拦截测试浏览器中的生成请求，不修改宿主源码。
