# v0.4.7：输出格式移除与已迁移规则拆分

## 根因与用户决定

v0.4.5–0.4.6 把输出文档拆成格式与剩余规则，并复制原世界书条目的启用、常驻及注入位置。名称追加“保留数据约束”没有隔离正文注入，可能继续向正文模型发送旧更新要求。协议定义逐句白名单还会因常见措辞差异保留整个指令组。

用户明确选择：完整、可识别的输出格式文档整条移除，不新增替代世界书或响应协议。未匹配分组没有通用的全局规则标准，本批不自动迁移它们；更新规则只按已迁移内容拆分，保留未承接部分。用户仍要求暂不推送。

## 实现与边界

`isMvuOutputDocument` 仅确认无 EJS、可解析、单一正式输出包装及对应的 format 字段；沿用对 UpdateVariable、变量快照和旧 _.set 格式的识别。正式输出文档整条删除，不再逐句匹配 JSON Patch 指令说明，也不拆分或自动迁移附加句子到表格 Note。

原有纯输出标记与快照删除继续生效。剧情标记、动态 EJS、非输出文档和无法安全识别的混合内容仍保留；更新标记或名称中的关键词不单独构成删除证据。转换报告区分输出格式由宿主接管与业务规则已经迁移。

`splitMigratedMvuRules` 通过来源路径与 schema 中实际保留的列级/表级/通配规则确认 check/note 已承接，逐项移除并收起空分支。不能仅凭另一条路径出现相同句子就删除，也不按分组名称推断全局含义。未知补充说明继续保留；YAML 文档节点定向更新，保留剩余部分的注释及原条目的启用、常驻和注入位置。全部承接且无剩余说明才删除整条。解析失败、EJS、共享/循环节点整条保留。

剩余规则没有新增填表承接位置，仍按普通世界书设置注入；报告明确提示该边界。它不等于规则已进入填表请求。本批不新增全局变量、独立规则表、逐表全局规则或宿主提示词改写。
