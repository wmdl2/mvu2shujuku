# 声明可空动态记录：实施与验收

本批接续顶层可空容器，基线 453 项；不重新进行上一轮综合审查。

## 行为与实现

明确声明为 `z.record(key, object.nullable/optional/nullish())` 或可空数组值的字典，逐条记录使用身份列加完整 JSON 内容列。支持根字典、单例内字典、动态父记录及多层关联；初始为空字典也按声明建列。JSON `null` 是存在的空值记录，`{}` / `[]` 是空容器，删除行或空单元格读回为缺失键。没有增加状态列，也不改变未声明可空的普通行表存储方式。

布局复用 `scalarValueCol` 与 `jsonObjectOptional`；原 codec 无须改动。writer 在完整记录边界校验、编码一次，现有 `updateCell` 和 `insertRow` 只接收字符串/数字。单列更新实际走 `updateCell`，不宣称覆盖未调用的 `updateRow`；当前回复的候选模板继续使用产品真实工厂，不复制一套测试实现。

保留内部路径、说明和业务规则；SQL 可局部修改 JSON，native 整格提供新 JSON。固定内部路径的范围/小枚举使用 CHECK，并接受所有模板初值中的哨兵；正常范围内的数字不额外展开成逐值放行条件。内部动态键/数组元素的约束仍只保留在说明并报告限制，不能据此宣称完整执行 Zod。

## 同批必要修复

- 只有子表字段的新对象也创建身份行，避免新增后代成为无法读回的孤儿；只有关系子表的中间记录不再生成虚假的空“描述”字段。
- 顶层数组/完整 JSON 组不再按同名嵌套字段的声明误建子表；公开夹具使用顶层“背包”数组与角色的“背包”字典，预检查实际复现了覆盖问题。
- 持久化重放的重复记录守卫使用完整祖先键和记录键；不同父记录的同名条目不再误拦截。同一完整标识仍会拦截，等待宿主重放。

## 边界与后续

新布局需重新转换；不自动迁移旧聊天。未声明的拆分组空值、扩展 VWD 支持范围、任意历史楼层多步原子性仍不在本批完成范围。完整记录中的私有 JSON 叶子不会因此隐藏。没有测试真实模型质量，也没有测得额度节省比例。

调试中另确认：规则写成单独占位键下再嵌套字段（例如 `记录 → ${名称} → 数量 → check`）会被既有 YAML 规则扫描忽略；本批保真测试使用已支持的点路径 `记录.${名称}.数量`。该解析缺口单列后续处理，不把换写夹具当作已修复。
