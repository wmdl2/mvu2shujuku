# 酒馆助手变量接口的启动顺序（2026-11-02）

## 问题与修复

酒馆助手父窗口提供 `TavernHelper` 命名空间，iframe 的裸变量函数由其 `predefine.js` 注入；父窗口不必存在同名裸函数。原适配会在没有原生绑定时也发布裸函数。作者按“先裸全局、再命名空间”选择接口，就可能命中无法委派聊天／全局作用域的接管函数。会话创建时助手尚未加载，也可能永久捕获缺失的原函数。

`applyWindowMvuShim` 现在只接管实际存在的裸变量函数，保留作者选择命名空间的能力。MVU 的非消息作用域在调用时解析宿主原接口，允许助手晚到；原生 receiver、消息数据库投影和写入守卫保留。没有新增变量存档，也没有修改作者脚本或提示词。

源码依据：酒馆助手本地受测版本的 `src/iframe/predefine.js`、`src/function/variables.ts`、`src/function/index.ts`。该行为与作者是否使用特定变量名无关。

## 原卡问题与范围

受测卡的作者 Schema 脚本保留了 TypeScript 类型注解。酒馆助手直接以 JavaScript 模块执行，实机报 `Unexpected token ':'`；原脚本与转换后脚本内容相同。仅供分析的类型擦除副本能执行并验证初值，但该副本没有进入转换卡或插件。静态提取出表格，不代表原 Schema 的自定义变换已经运行。

作者混合正文格式条目仍含旧更新标签要求。原 MVU 额外模型的条目名过滤不能自动处理所有混合正文说明；保留的业务示例与统一填表适配说明分别核对，不为删除标签而猜测改写自然语言。此次没有新增提示词规则。
