# Schema 默认值与延后初始化验证（2026-10-31，未发布）

本轮保持现有行表／JSON 划分、作者规则原文和变量路径，修复两处适配问题；没有为单个角色卡增加识别分支。

## 结构默认值只编码一次

动态行表缺少初始记录时，变换字段可能从 Schema 取得默认值。输出类型无法静态确定的字段保留完整 JSON；原实现先把数组／对象默认值转成 JSON 文本，又把该文本编码为 JSON 字符串，导致只指定业务键的 SQL 新增把数组 `[]` 读回成字符串 `"[]"`。

`applyDeclaredShape` 现在对这一分支直接使用 Schema 的原始默认值，再执行原 JSON 列编码。没有把所有看似 JSON 的字符串自动解析，原始字符串 `"[]"` 仍是字符串。

公开回归通过真实 SQLite 执行生成 DDL，省略普通列插入记录，覆盖空数组、双元素数组、对象、外观为 JSON 的文本、数字、布尔和 null，并使用产品读回实现验证类型。测试不依赖外部角色卡或本地隐藏源码。

## 无变化初始化不覆盖后续记录

纯 Schema 开场任务可以等待作者登记后才完成。原实现即使校验前后数据相同，仍把捕获的完整快照交给开局整表导入；在此期间正常回复已经新增记录时，旧空快照可能较晚落库并覆盖新值。

现在仅对没有内联初始化／更新块、Schema 已完成且输入输出 `stat_data` 相同的任务登记完成和来源指纹，不提交整表。实际变换、仍需校验的延期任务以及内联开场语义保持。

公开并发回归直接运行生产初始化函数，在校验等待期间新增记录，确认无变化初始化不提交旧数据且后续通知不重跑。原有非幂等初始化、已有存档基线、内联分支及真实写入回归继续覆盖保留路径。
