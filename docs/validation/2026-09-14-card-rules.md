# 规则迁移、字段扫描与关联提示验收

本批由实际卡的两个反馈触发：转换后仍保留 `[mvu_update]`，以及关系数据的主记录表多出无用 JSON 列。
承接 [JSON 与合表验收](2026-09-14-json-path.md)，版本仍为 0.3.18 未发布，Git 基线 `d102648`。

## 原因与修改

1. `check` 的自然语言行尾含 `（op: delta, value: -1）` 时，YAML 会误当嵌套映射并报错。
   旧逻辑因此回退正则，并为避免丢业务保留整条规则。现在规则提取与删除判定共用受限预处理，
   将这种完整单行说明按字符串解析；业务条件保持，其他损坏 YAML、续行和混合 EJS 仍保留。
2. 不同函数复用短变量名时，旧扫描把其中一次数据别名声明应用到整个卡。现在将扫描提取到
   `src/status-usage.js`，按来源、词法块及声明解析可识别别名；处理参数遮蔽、表达式体箭头函数、
   闭包与 HTML 脚本，避免从普通字符串和注释补列。没有按卡名、字段名或脚本大小制作过滤规则。
3. 填表提示统一称「关联字段」，直接列出实际列名与来源，说明所有定位字段必须同时匹配。
   删除关联记录或变更标识值的同步操作仍须在本次填表中完成。没有新增 SQL `FOREIGN KEY`
   约束，也没有更改物理列名、布局属性或读写协议。

例如通讯记录通过「通讯录_联系人」关联「通讯录表.联系人」，与「消息标识」共同定位一条消息。
通讯录保存联系人资料，消息表保存多条历史记录，两个表各有用途，不应将消息历史重复存回附属 JSON 列。
