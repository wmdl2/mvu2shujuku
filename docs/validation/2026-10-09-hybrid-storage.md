# 混合存储与根对象映射验证

2026-10-09，0.8.0 未发布工作树。本记录区分当前回归、上游执行对照、隔离宿主和十五张卡完整游玩；前者不能替代后者。

## 当前实现

- 固定字段保留普通列，稳定顶层字典保留行表。普通记录的可写“扩展数据”JSON 保存未展开字段，包含其内部隐藏字段；复杂后代、数组及说明与值共属一个对象的 VWD 使用完整 JSON。
- 内部 `$` 与所属对象共同存储、删除和替换；发送副本递归省略 `$`。独立顶层 `$` 沿用原消息 `variables[swipe].stat_data`，不另建存档。`_` 是普通业务字段，前缀不产生权限。
- 新转换不增加全局动态变量兜底表。启用的 Zod 根 `record`／`passthrough`，或实际 MVU 根元数据 `extensible: true`／`recursiveExtensible: true`，直接映射根对象。仅有 `template`、关闭声明及禁用的开放 Zod 均不自动开放根。
- 根容器的显示组名不作为原变量名参与防串卡检查。Schema 后的检查与真实 writer 使用同一布局契约。
- 先按源布局提取明确权限，再按最终布局重新绑定业务说明及已唯一确认的标题；完整 JSON 的路径相对于实际内容列。新增数组元素仍说明为“新增内部路径”，不是新增数据库身份行。原世界书业务文本保持原样。
- 原消息中未声明的根数据可保留并通过原变量接口读取，常见于作者脚本动态创建；直接数据库写入未映射根明确失败。这是映射范围边界，不能宣称任意公开动态根都能由 SQL 填表维护。
- 新转换只支持实际 SQLite。作者脚本写入在公开 SQL 能力未就绪时有限等待后失败；不把 getter 缺失直接判成原生模式，也不承诺取消宿主内部所有原生填表请求。
