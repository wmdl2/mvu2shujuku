# v0.4.6：表格说明与当前输出协议

## 用户决定与默认行为

用户批准参考数据库默认职责分工：表格说明共用业务约束，由宿主当前填表提示词与表格呈现决定操作语法和编号。不新增严格 JSON 定位说明，不逐表重复多协议选择；关键范围变化先说明并确认。用户仍要求暂不推送。

参考受测数据库 `naiv1.0.0` / `fd91407f84d7968473e82b90d93f22822cb3b259`：`settings-write-service:setStorageMode_ACU` 切换存储模式并更换默认全局填表提示词；`prompt-prepare` 将同一份 note 和操作触发条件投影为原生表格或 SQL 注释，不按模式改写业务正文。实际组装的 8 张默认表 note 没有模式分支，但操作触发条件仍含 SQL 示例。

## 变更范围

- 数值、单例与整组 JSON 表的业务说明不再固定 `row_id=1`；初始化和更新限制改成“更新现有记录”“禁止新增或删除”，只读限制及可写路径保持。
- 删除逐表 native/SQL 行号选择说明；多层数组继续提醒先确认来源，不把来源内部序号直接用作本表定位标识。
- 双模式 JSON 说明只区分本次要求原生行操作时提交完整新 JSON、本次要求 SQL 脚本时按允许路径局部更新。
- SQL 示例仅在本次输出要求 SQL 脚本时适用，保留实际语句、转义和不得照抄示例值的限制。纯原生模板不包含生成器附加的 SQL 示例。

不修改数据库宿主、不拦截模型请求、不切换用户填表开关或更改响应结构。严格 JSON 分支草稿已撤回。已有模板需要重新转换或重新导出以获得新说明，旧聊天不自动改写。
