# 每次调用独立的写入结果

## 范围与契约

`table-writer.js` 新增 `writeStatDiffToDbResult`，返回 `{ ok, plannedChanges, failureReason }`。
运行时差异写入、开场候选追平和当前回复规划直接检查本次 `ok`，失败诊断使用本次原因。
旧 `writeStatDiffToDb` 数字接口及 `lastStatWriteFailed` getter 保留，两种入口共用同一内部算法。
新接口不读写旧 getter。

`plannedChanges` 与旧返回数字一致，是计划差异数量，不是成功次数或实际 API 调用次数。
无操作可以成功返回零，规划拒绝可以失败返回零；部分操作成功后失败不承诺回滚。
三处回放窗口继续保留“标记失败并跳过当前操作”的行为，普通失败终止后续写入，
`updateRow` 失败后原有逐格降级仍可成功。已有规划异常仍抛出。

本批未改变表结构、SQL、宿主 API 载荷及调用顺序、SP 保存/回放协议。
调用方仍须验证会话并串行写入；结果隔离不等于允许并发写同一宿主。
