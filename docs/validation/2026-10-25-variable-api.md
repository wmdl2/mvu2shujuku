# v0.8.4 变量接口统一适配（2026-10-25）

本轮从上游接口清单和注入代码核对行为，不根据角色卡字段增加分支。本记录对应 v0.8.4，发布构建和分阶段验证范围见[收尾记录](2026-10-25-release-v0.8.4.md)。私有角色卡、世界书和原始请求不纳入公开夹具。

## 基线与原因

核对 MVU 本地源码快照的 `src/function/global/index.ts`、`src/function/initvar/variable_init.ts`；该快照没有 Git 分支信息。酒馆助手参考 commit 为 `87ca341a2a2279f4c18cd1918c5ae9dbd1dac492`，核对 `src/function/variables.ts`、`src/iframe/predefine.js` 和 `src/function/chat_message.ts`。实机为 ST 1.18.0、TH 4.11.3、提示词模板 1.17.9、用户安装的数据库 1.2.9；数据库参考库的 1.3 不作为受测版本。

旧实现分别包装 Mvu 和部分裸函数，未统一命名空间与 iframe 绑定；也没有把替换、合并插入和仅补缺失字段作为不同契约处理。由此产生入口间状态不同、默认作用域变化、遗漏操作等问题。仅检验某个入口能读回数值，不能证明接口兼容。

`src/variable-api.js` 是实际运行时调用的同一个工厂。对象合并、数组覆盖、路径删除和克隆使用 Lodash；非消息作用域交回宿主公开接口，保留原 receiver、参数及返回形式。不复制提示词模板项目的变量模块。

## 接口清单

| 入口 | 本轮契约 |
| --- | --- |
| `getVariables` | 酒馆助手默认聊天作用域；仅显式 `type: 'message'` 投影数据库，辅助变量仍来自原作用域；返回独立副本。 |
| `replaceVariables` | 整份替换；未提供 `stat_data` 也不暗中解释为“保持原变量”。布局无法无损表达结果则拒绝。 |
| `updateVariablesWith` | 以完整视图调用 updater，接收其返回对象；同步及异步 updater 均支持，不把 `undefined` 猜成原快照。 |
| `insertOrAssignVariables` | 对象递归合并，右侧数组整份替换，保留未涉及字段。 |
| `insertVariables` | 只补缺失值，已有值和数组优先。 |
| `deleteVariable` | Lodash 路径语义，返回 `{ variables, delete_occurred }`；不把不存在路径的返回值另作解释。 |
| `getAllVariables` | 保留宿主合并的辅助变量；消息 iframe 使用所属楼层，脚本使用转换卡既有的当前状态视图，不向脚本询问所属消息号。加载窗口只返回宿主实际存在的变量并标记未就绪，不编造数据库默认值；此结果不能作为完整快照提交。 |
| `getChatMessages` | 裸函数及命名空间的 `data.stat_data` 投影相同楼层；保持原同步/Promise 形式，不改写真实消息；不虚构未选中 swipe 的快照。 |
| `setChatMessages` | 仅正文等非变量操作继续委派；当前消息的 `data` 经过同一变量写入管线，再把原消息实际存储的数据交回宿主，避免复制全部映射状态。 |
| `Mvu.getMvuData` | 显式非消息作用域仍委派；保留转换卡既有的无参数读取当前状态及仅提供 `message_id` 的便捷形式。辅助元数据不再丢弃。 |
| `Mvu.replaceMvuData` | 使用同一变量提交管线，保留旧转换卡的成功/失败布尔值约定；解析结果的业务处理标记和 Schema 凭据不因克隆丢失。 |
| `Mvu.getMvuVariable` / `setMvuVariable` | 保留既有 Lodash 路径、VWD 与异步事件语义；未知分类不误读 stat。 |
| `Mvu.getRecordFromMvuData` | 返回请求的记录；未知分类为 `undefined`。 |
| `Mvu.parseMessage` | 继续使用既有 MVU 命令解析、事件与校验管线；提交解析结果不重复执行 Schema 变换。 |
| `Mvu.reloadInitVar` | 从已转换模板补缺少的顶层变量，按转换世界书去重；不重置已有根对象，不重写展示和差量记录。 |
| `Mvu.getCurrentMvuData` / `replaceCurrentMvuData` | 保持既有转换卡的当前消息兼容别名。 |
| `Mvu.events` / `registerSchema` | 沿用已有事件与 Schema 适配；本轮没有新增事件协议。 |
| `Mvu.isDuringExtraAnalysis` | 仍为 `false`：转换卡不再启动 MVU 的额外解析引擎；不把数据库 SQL 填表活动擅自当作该引擎。 |

消息写入需要 `await`；SQLite 持久化不能承诺酒馆助手原生内存写入的同步完成。其他作用域保留原同步/异步返回形式。错误的 TH 写入拒绝 Promise，不伪装成功；`Mvu.replaceMvuData` 继续返回 `false`。任意历史消息写入、一次提交多个消息变量以及 `swipes_data` 独立状态写入仍明确拒绝；已有的历史只读能力没有扩大为写入接口。同步历史读取需先完成宿主回放准备，可使用 `waitGlobalInitialized('Mvu')` 等待；未就绪不返回当前楼冒充历史。

`reloadInitVar` 的输入仍是转换时已编译的初值，未新增对任意外部世界书动态 InitVar 的重新转换。旧版本转换卡无需重转才能使用本轮接口修复。

## 注入与存储

统一适配包含裸全局、`TavernHelper` 命名空间及助手 `_bind` 生成的 iframe 函数。绑定时保留真正原始函数；Lodash 合并可能共享带自定义原型的命名空间，不能再把该外观当成原始后端。切卡、iframe 导航、晚加载宿主函数和只读描述符分别验证；安装失败不再完全吞掉诊断。

宿主渲染事件中仅准备只读快照（包括当前楼层），不初始化或改写数据库。当前运行时尚在加载时可读取该楼层已准备的宿主回放结果；准备与发布均检查会话，切换后不发布旧结果。

原消息与数据库的分流使用已经宏展开的实际布局路径，避免冻结的 `{{user}}` 根名与实际表格路径不一致而误分流。声明隐藏字段的写入位置、展示过滤和未映射脚本根数据的既有策略保持。

## 提示词范围

世界书正文屏蔽继续对齐 MVU 额外模型规则：只有更新标签的条目整体不发给正文，混合状态展示不会自动被拆出。旧格式处理继续保守：完整明确的纯格式在请求副本排除，混合业务、真实路径和值保留，统一填表适配说明要求使用数据库协议。说明原文保持；后续将完整生成说明在请求副本中前置，纯旧格式识别范围保持。
