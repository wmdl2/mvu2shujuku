# VWD 默认关闭与候选构造验收

VWD 动态说明保持实验、默认关闭。普通转换继续使用静态说明，不新增说明元数据列或拒绝策略。
内部实验路径在候选构造前检查未折叠的说明，初始空说明也不能绕过拒绝。

本轮审核发现测试工厂与浏览器安装器仍维护两份候选构造实现；工厂通过 `toString` 内联时还
缺少外部 `normalizeCellForSync`。已让安装器直接调用同一工厂，并把辅助函数收进工厂作用域。
新增隔离 VM 用例先复现失败，修复后通过。候选构造仍只修改内存副本，保持原提交与会话边界。

四项默认关闭对照原来依赖被忽略的本机旧源码，现改用 `test/vwd-static-before.json` 中的公开
合成样本冻结结果。冻结数据只用于检查本次实验未改变旧行为，不把既有 pair 写入缺陷定义为
正确语义。后续独立修复该缺陷时需要有意更新对应断言，不能仅为通过测试恢复错误行为。

## 尚未解决的边界

旧式 pair 整段写入可使单元格带数组，SP hydrate 报 `val.replace is not a function` 并回退
native。本次实机再次出现 `sqlReady:false`，**不算 SQLite 写入验证通过**。此前当前实现和
冻结基线的同场景均已复现，属于独立的既有缺陷。控制台存在这些已知错误；结果中的
`browser-errors: []` 只表示没有收集到未捕获页面异常，不能表述为控制台零错误。

VWD 的 note 同步、值/说明/提示协调提交及说明历史回放未实现；删楼回退仍待独立验收。
此次通过的是默认关闭与实验拒绝契约的返工收尾，不是动态 VWD 功能上线。
