# MVU 更新前回调正文写回（2026-10-07，v0.7.0）

用户授权修复此前确认的 `BEFORE_MESSAGE_UPDATE.message_content` 遗漏。基线为 v0.6.0 后尚未发布的状态展示修复；修复归入 v0.7.0，没有增加提示词措辞；下述原受测构建和指纹保持历史记录。

## 原因与行为

原 MVU 本地快照在变量更新后发出回调，并采用 `message_content` 作为最终消息文本。本扩展此前发出同一回调、采用 `variables`，却丢弃了正文结果；首楼合并初始化和后续更新两个入口均存在遗漏。实际探针确认变量更新成功而正文不变。

本轮两个入口都保留正文结果，在变量提交成功后保存。变量不变也采用正文修改；正文必须为字符串。未修改正文不制造额外保存。回调正文、回复状态块清理和所需占位符共用实际消息保存实现。

聊天、来源消息对象、原文本和 swipe 守卫贯穿回调等待及保存重试。流式生成结束后才处理后续更新；变量提交成功就登记原来源，正文失败只重试文本，最多10次，不能重复增量命令或作者回调。保存后登记修改后的更新块/首楼来源，避免刷新和轮询重放。进入已有存档继续遵守历史基线，不批量重写历史。

变量和正文没有跨系统事务：连续正文保存失败时变量可能已经成功提交。缺少助手消息接口时沿用既有内存回退，不能承诺落盘。首楼来源守卫同时防止异步回调期间的分支编辑覆盖新来源。
