# 历史缓存优化验证

本轮优化本插件的历史读取成本，没有修改数据库、表结构、业务提示或历史写入权限。本轮以 0.8.2 候选包完成行为验证，随后收尾为 v0.8.3；数据库受测为 1.2.9 / e445c967。

## 改动

`src/message-history.js` 使用存储对象及全部嵌套属性的只读校验记录替代每次读取时序列化整段聊天。校验保留父子容器引用、字段、数组长度与值，深层原位修改也会失效；字符串内容无需每次重编码。新代次仍检查 JSON 可序列化性，不修改宿主消息或安装代理。

布局也使用属性记录校验。聊天、消息数组、API、swipe、已发布运行时对象及提交回调仍可使缓存失效。等值运行时对象重新发布仍保守失效：公开 API 没有足够的同步隔离版本信息，不能按最终值相同认定来源相同。

宿主返回的历史快照先建立楼层索引，保留重复编号首次命中的行为。投影处理超过约 8ms 时让出主线程并核对代次，整批有效后才发布。`src/extension-runtime.js` 对连续通知的后台准备采用 120ms 防抖，立即失效旧缓存；显式 EJS／助手准备仍能直接执行并共享同代次任务。卸载回调时清除后台定时器。

## 定向验证

`test/message-history.js` 的 20 项相关检查通过，包括：

- 批量历史读回、并发准备复用、返回副本与原消息脚本数据实时合并。
- 命中读取不再序列化宿主数据帧，深层等长字符串修改仍使缓存失效。
- 数组换位／增项、字段增删、布局原位修改、聊天／swipe／运行时变化。
- 让出主线程期间发生变化时拒绝旧结果，不发布半批数据。
- 连续三次提交通知只安排一次后台准备。
- 生产工厂内联后在没有 Node 外部作用域的 VM 中运行。

命令：`node test/run-tests.js --grep '历史接口|历史读取|历史缓存优化'`。

随后同一冻结源码执行一次完整公开回归，977 项全部通过；根构建和语法检查通过，行为冻结阶段源码／构建与受测安装包指纹相同；v0.8.3 的版本收尾核对见后文。

## 性能对照

相同合成输入、实际生产工厂、桌面 Node 22 单次对照。模型／宿主历史接口为受控替代；不计真实 SQL 历史回放。

| 消息数 | 缓存读取次数 | 修改前 | 修改后 |
| --- | --- | --- | --- |
| 50 | 50 | 5.2ms | 4.4ms |
| 200 | 100 | 18.5ms | 11.4ms |
| 500 | 100 | 74.1ms | 20.9ms |
| 1000 | 100 | 152.3ms | 39.7ms |

修改后的命中阶段没有重新序列化聊天数据帧，也没有新增宿主历史回放。依然需要检查数据属性并复制返回值；不是常数成本，不据此推算手机倍率或承诺消除全部一秒停顿。
