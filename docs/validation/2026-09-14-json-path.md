# JSON 局部更新与固定附属对象验收

本批承接[语义验收](2026-09-13-semantics.md)，版本仍为 0.3.18 未发布，Git 基线 `d102648`。
关注转换后额外引入的填表成本；保留 native，不新增其 JSON 深层补丁协议，不迁移旧聊天。

## 修改范围

- 现有可写 JSON 列在 SQLite / 双模式模板中增加路径更新说明。SQLite 专用模板仅在能从实际值
  确认公开叶子路径时给出局部替换示例；空容器、只有私有字段或无法可靠表示的键不猜测示例。
- 去掉与局部更新冲突的整段重写要求，保留可写路径、未改字段及类型、初始化和定位约束。
  明确 `json('null')`、布尔值、对象/数组与 SQL 字符串的区别，以及数组索引、删除和追加规则。
- 对明确由 Zod 声明为固定结构的附属对象，固定字段并回父表普通列。完整逻辑路径、各字段的
  范围、枚举、布尔类型、只读和隐藏语义保留；展平后不再以下划线开头的只读列集中注明实际列名。
  动态记录及数组继续使用各自结构，不因两个样本形状相同就合并。

具体契约见[数据映射](../data-model.md#json-列的-sql-局部更新)。没有新增可见状态列。

## 成本证据与边界

同一份 40 物品的公开合成 nullable 背包，每个物品含名称、数量、说明，只把物品 1 的数量从 10 改为 9。
单次更新片段的 `o200k_base` 计数如下；不包含请求输入、消息协议或模型解释文字。

| 输出形式 | 字符数 | token |
| --- | ---: | ---: |
| MVU JSON Patch | 51 | 25 |
| native 完整 JSON 单元格 | 2445 | 1091 |
| SQLite 路径 UPDATE | 71 | 25 |

此样本说明局部更新能够避免复述未改 JSON。SQLite 路径函数不减少模型读取的原始数据，
而新增的每表说明也有输入成本；不能据此宣称整次请求比 MVU 更省。普通非 JSON 表不增加这段说明。

固定附属对象使用 `状态={金币:1,附属:{左:{值:1},右:{值:2}}}`，并为所有固定键提供相应 Zod 声明。
在同一份实现、相同双模式配置下，只将 `collectColumns` 的固定声明优先分支恢复为旧条件
`hasDynamicDescendant` 作为对照；不是与整个 `d102648` 版本混合比较。

| 模板组件库存 | 合并前：字符 / token | 合并后：字符 / token |
| --- | ---: | ---: |
| DDL | 391 / 135 | 275 / 103 |
| note | 338 / 237 | 143 / 90 |
| 四类触发说明合计 | 277 / 164 | 131 / 66 |
| 各表 content 的 JSON 序列化合计 | 96 / 53 | 58 / 37 |
| 表数 | 2 | 1 |

token 使用 `o200k_base` 对各组件分别计数再求和。组件不一定同时进入实际请求，不能把库存下降比例
当作整体模型成本降幅，也不能外推动态记录或大型固定结构。原有实际请求成本另见
[提示词测量](../benchmarks/prompt-2026-09-13.md)。真实模型效果由实际使用继续观察。

固定字段合并对重新转换后的布局生效；旧聊天不自动迁移。VWD 动态描述持久化、整行/整组 nullable
等既有边界仍见[兼容清单](../../COMPATIBILITY.md)，不计入本批已修复项。
