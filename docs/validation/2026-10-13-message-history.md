## 上游与实现

[数据库 PR #31](https://github.com/AlbusKen/shujuku/pull/31) 于 2026-10-12 合并，merge 为 `ab500342f4dd005682ab73e0e00c94734e5fc998`。本批参考与实际宿主采用 `e445c967d8198240bdf799b85a5250e625f78062`；上游追加原始存储引用守卫，包含 JSON 字符串载体的变化检查。发布包仍为 1.2.9，实际 index SHA-256 为 `3ebdb5d6931ed47f5fe1323d80476704ca9642899a5de01cd16661820e4a7f19`。按接口能力判断，版本号不能区分同为 1.2.9 的旧包。

`src/message-history.js` 实际由扩展装配并调用，仅读取 `exportTableSnapshotsAtMessages(indices)`。SQL、checkpoint、各楼层边界和失败定位交给宿主原引擎，不引入独立 SQLite、私有回放算法或存档。接口仅读取当前聊天和选中隔离槽，不执行历史写入。

EJS 的公开 `prompt_template_prepare` 事件与 `evalTemplate` 包装在原同步变量调用前等待准备；显式执行上下文保留消息归属，无上下文填表调用默认当前值。`waitGlobalInitialized('Mvu')` 及前端发现、表格提交回调补齐准备。`getVariables`、`Mvu.getMvuData`、EJS getter 使用同一历史读取；裸全局 `getChatMessages` 的普通 `message_id/data` 结果按各消息投影，保留原同步／异步形式、正文和辅助数据。`include_swipes` 的其他返回形状保持原文，不创造未选中 swipe 的独立状态。

缓存只保存数据库投影，读取时实时合并目标消息的原生脚本数据，避免脚本删除后旧值从缓存复活。缓存按聊天代次、布局、消息数组、swipe、完整存储内容和已发布运行时对象校验；表格回调显式失效。同代次并发共用任务，已准备楼层不重复回放；失败整批不发布半份结果，后续准备可重试。同步读取先于准备完成时抛出 `MVU_HISTORY_NOT_READY` 并启动准备，不伪装为空对象或最新楼值。

宿主接口没有同步隔离标识；缓存不跨其已发布运行时或表格回调复用，不宣称捕获宿主发布前任意私有设置变化。旧宿主无接口时保留已有同步快照备用读取，仍不能回放历史 SQL。任意历史写入和未选中 swipe 的指定读取继续拒绝。
