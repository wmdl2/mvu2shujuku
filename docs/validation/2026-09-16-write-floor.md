# 普通脚本写入的楼层归属修复

后续已补强同楼混合更新：可由单次 CRUD 完成的修改保留差量，多次调用合为一次导入；
本页保留楼层修复阶段证据，当前批次规则与额外成本见[批次验收](2026-09-16-atomic-batch.md)。

普通 `Mvu.replaceMvuData` 现在绑定调用时的最新 AI 回复。新回复还没有可安全追加的表格记录时，
直接将最终候选快照正式提交到该楼；同楼后续修改在能证明 CRUD 保存归属时继续差量写入。
无变化不建表帧，导入失败不退回旧楼 CRUD。开场初始化保持原有路径，不增加表格列或填表提示词。

此前，同一调用修改普通字段时可能写回开场楼，修改数组并触发整批导入时却保存到新回复；
删除新回复会得到不同结果。[修复前诊断](2026-09-16-rollback.md)保留对应证据。

## 保存楼层的判定

受测 SP API 没有公开的当前隔离作用域 getter。插件采用充分条件，不猜当前作用域：
检查此前 AI 消息出现的每个作用域，目标回复必须也有可追加的 V2 帧。
这样无论哪一个作用域生效，SP 都会选中目标回复；完全没有历史帧的作用域，SP 本就回退到最新 AI 回复。
仅有其他作用域的表帧不能通过检查。旧格式、不可识别的数据或多个作用域未在本楼齐备时，走快照路径。
这类聊天可能每批都需快照，不承诺总能恢复差量。

调用与消息解析开始时捕获目标消息身份；合并窗口、候选规划、重试和实际 API 调用沿用同一守卫。
删除目标、换 swipe、编辑、后来出现新 AI 回复或切聊天都会取消旧任务。队列合并保留原有来源校验。
每次 CRUD 前再验证楼层条件；若表帧变化，停止该调用并按实际数据库重新规划。
只读取历史帧，创建与持久化仍交给 SP 的正式入口，不手写 checkpoint。

## 本地性能测量

Node 22.23.2 / Linux，公开合成输入；中位数。脚本与[原始结果](../benchmarks/fixtures/write-floor-2026-09-16.json)可复现。
楼层检查不复制单元格内容：1,000 条消息约 **0.012 ms**，10,000 条约 **0.116 ms**。

| 数据行数 | 表格 JSON 大小 | 原有内存差量写入 | 构造候选快照 |
| --- | ---: | ---: | ---: |
| 100 | 6,224 字节 | 2.51 ms | 3.45 ms |
| 1,000 | 39,526 字节 | 9.84 ms | 18.26 ms |
| 10,000 | 399,528 字节 | 63.88 ms | 148.31 ms |

差量与快照使用同一真实核心实现，测量环境中的宿主是内存适配器。此表不含 SP 保存、磁盘 I/O、
回放耗时，也不是所有卡的性能保证；大 JSON 单元格、多作用域或旧格式需要另按实际数据观察。
通常新回复只增加首次快照构造成本，同楼后续小修改保留差量；这项修复不增加模型提示内容。
另补 pair 编码后的相等检查：未变化的 `[值, 说明]` 不再因与物理标量形状不同而重复写库；
保留新行及实验动态说明所需的原子写入。使用线性筛选，避免批量删除候选时反复移动数组。

## 限制

不修复已被旧实现改写的历史帧，不承诺历史 message_id 定点写入。已进入宿主的调用无法撤销；
守卫会停止后续操作并避免报告成功。既有多步 CRUD 的整体原子性边界仍在；本次没有将其扩展为事务。
VWD 动态说明仍默认关闭。
