# 转换架构与产物

解析与公共数据操作优先使用已有实现：EJS 代码边界共用原解析器，JavaScript 词法共用 Acorn，路径读写使用 Lodash。不得另写简化规则代替这些实现；存储后端耦合的接口仍需按契约适配，不临时篡改宿主共享消息/缓存。见[实现和验证](validation/2026-10-08-upstream-reuse.md)。

兼容修复以对应版本 MVU 原实现的行为为标准。能合法复用的执行逻辑优先复用，数据库适配只改变存储与协议表示，不能自行改变对象删除、数组移动、缺失值、校验、事件或失败语义。默认展示过滤不等于存储隔离或写入权限；拆分保存必须另行证明结构操作一致，不能仅凭最终公开快照猜测隐藏子字段对应关系。接口无法提供等价实现所需信息时应明确限制并重新讨论适配方案，不用卡片特例或推测弥补。

变量存储位置兼容必须覆盖接口行为。当前原生变量函数调用由 EJS 运行时上下文按动态参数适配，历史读取使用数据库帧；不支持的历史写入先拒绝，不能静态改写后忽略选项。实现与边界见[变量适配](validation/2026-10-08-variable-adapter.md)。

## 项目目标

本项目是 SillyTavern 原生扩展，将使用 MVU（MagVarUpdate）的角色卡转换为 SP·数据库角色卡。

转换内容包括：

- 解析 `[InitVar]` 世界书和问候语中的 `<initvar>`。
- 无可用初始变量时，允许卡内已启用注册 Schema 的完整静态默认值提供初始结构；缺少必填初值、动态默认或无法解析的必填声明时中止。
- 新转换以完整 JSON 保存已映射根变量（开放根整体保存）；兼容旧单例、行表、关系表和数组表。容器存在状态的决策见 [布局设计](design/layout-planning.md)。
- 将可识别的结构、类型及权限映射为表格约束和列说明；更新业务原文通过统一填表适配说明衔接宿主协议。
- 保留用户业务脚本，移除可确认已被数据库取代的 MVU 引擎或纯 Schema 启动块。
- 提供 `Mvu.*`、`getVariables`、`updateVariablesWith`、`getAllVariables` 等运行时兼容接口。
- 让原卡前端、EJS、多开场和卡内业务脚本在数据库卡中继续工作。



## 转换器职责与独立填表基线

本节记录 2026-10-08 确定并实施的转换职责。统一条目及请求副本处理见下文和[验证记录](validation/2026-10-08-fill-adaptation.md)；这不表示任意作者脚本、完整剧情或真实模型质量均已验收。

数据库的独立填表请求在任务分工上对标 MVU 的“额外模型解析”：正文模型负责叙事，填表请求根据正文、状态和业务要求产生变量变更。两个请求可以共用模型或 API；“独立”指请求及任务，不要求另一个供应商。本轮更新迁移以独立填表为基线，不新增“随正文输出变量更新”的模式，也不将正文与填表共享随机结果作为普遍兼容目标。已有剧情、前端和共享状态展示按原职责保留。

转换器负责将作者声明的数据结构映射到表格，提供类型、记录身份与必要的地址对应，并维持变量 API、Schema 校验、事件和提交语义。原业务代码读取由数据库还原的变量对象，修改后经共用候选构造与写入层持久化。存储映射问题应修复通用契约，不以卡名、角色名或某句自然语言为补丁入口。

业务自然语言应尽量原样保留，由填表模型结合上下文、表结构和已有说明理解。转换器不把每一句自然语言解释成声明式约束，也不因相对地址或业务名称未形成完整 JSON 指针就要求增加作者措辞识别。业务文本不再经过静态路径绑定和只读函数白名单才能保留；实际执行的数据/API、类型及权限声明继续按其结构契约处理。沿用已有表结构和列说明，不默认新增原变量路径映射、整份变量 JSON、全表路径/类型清单或逐表重复同一总说明。

MVU 与转换后的独立填表都可以使用作者世界书和当前变量内容。字段缺少描述文字（例如 Schema 中没有 `.describe()`）不等于模型缺少更新依据；不能仅凭表说明未复制某项 Schema 声明就认定兼容缺口，再追加整套字段类型清单。验收应核对实际请求中的原业务条目、可见变量和地址是否保留；只有这些信息确实丢失、被错误屏蔽或映射失效时，才修复对应链路。Schema 的执行与校验职责不能由追加提示文字代替。

新转换的模型输出仅使用数据库宿主 SQL 填表协议，使用前须启用实际 SQLite 模式；停用的转换参数按 SQLite 迁移并报告，宿主全局设置与旧聊天不自动变更。保持 MVU 行为不要求模型保留 JSONPatch 输出语法；对象操作与表格操作通过布局及相同业务校验衔接。运行时已有 MVU 命令兼容入口与模型输出格式是不同职责。JSONPatch 一词也可能是业务数据，不能仅按关键词删除作者代码、展示或字符串值。

EJS 代码由提示词模板插件在提示词组装阶段执行，正文模型只接收渲染结果，MVU 核心不是 EJS 执行器。同一次作者计算可以同时生成叙事指引与更新要求；开启额外模型解析后，共享条目可能在不同请求重新渲染，原 MVU 不保证跨请求共享骰子，EJS 编译缓存也不是结果缓存。因此先核对实际条目路由、渲染次数和原触发阶段；独立填表本身不能证明更新脚本只在填表侧执行。纯更新计算应有明确执行归属，避免在正文或多个说明位置重复执行；混合职责不能仅凭含随机数就整条搬走。状态写入还需核对成功、失败、重试、取消及来源变更的行为，不能只放宽函数白名单或按楼层缓存所有结果。

**统一填表适配（v0.8.0）。** 在现有世界书新增一个常驻 `[M2SJK]填表适配说明` 条目。作者业务源内容保留，只继续执行既有 MVU API/宏兼容改写；不逐句替换旧术语、原路径或另造执行副本。静态结构、类型、权限和已支持的表列说明仍按既有契约生成。

请求副本只排除完整且明确的旧格式语法、空数组或显式占位目标示例。格式槽含业务检查时，仅去掉可确认的外壳和占位载荷，原检查正文保留。真实目标/值的操作数组、混合业务、不完整结构、动态格式、业务注释以及 YAML 锚点/别名保留；协议名称作为业务数据时也保留。不会静态执行作者代码来推断纯度。

统一条目包含静态可读说明和私有 EJS 注释标记。当前转换卡的元数据、标记及数据库无显式上下文的 `evalTemplate` 调用共同限定请求适配入口；正文/预览的显式上下文不走该请求清理。完整源内容匹配成功后才应用请求副本，不按零散关键词删内容。每个渲染段只保留一份统一说明；不跨不同请求缓存计算结果。源世界书不被运行时改写，填表选择仍由宿主/用户控制，须包含统一条目；请求副本处理依赖提示词模板入口。

填表模型按本次数据库提供的表结构、数据和输出协议工作，无需引入“组”的概念或新增动态分组信息。跨组读取与更新依赖由用户配置分组处理，转换器不自动分组，也不承诺跨组联动。统一适配说明沿用当前数据库请求的范围；作者EJS的直接宿主写入仍按已有执行契约单独检查，不由模型提示词承担写入隔离。

不默认新增原变量路径清单或布局对应提示，继续使用已有DDL、列说明和JSON列内部定位说明。内部路径映射与转换报告保留，不因此复制到模型提示词中。只有实际出现目标定位歧义时，再依据具体证据讨论是否需要补充说明；本次统一条目方案不增加此机制，也不改写作者原说明。既有结构化类型/权限、数据映射和列说明继续按已验证契约处理。

## 转换时

`sheet-identity.js` 按受测数据库的算法 v1 与固定 pinyin-pro 版本计算物理表名；`schema-layout.js` 的顶层和派生表共用冲突分配，不改逻辑变量路径。不同开场是否属于旧名迁移由作者运行时 Schema 决定，不能据显示名或相似用途自动合并。

`update-rule-migration.js` 生成统一适配说明，并为完整静态旧格式规划请求副本排除区间。业务源文、随机计算与具体操作数组保留原位置，不再依靠静态路径绑定或只读函数白名单将混合条目拆成多个可执行副本。更新专用标题仍由 `fillTitle` 兼容宿主名称过滤，正文事件过滤同时识别新旧标记。

格式规划保留 source offset，不重序列化作者 YAML；只确认明确的标签结构及空/占位操作载荷。分析槽正文、未知补充字段、真实目标/值和 EJS 动态格式保留；同条目其他 EJS 不妨碍独立静态格式处理，但不删除任何控制代码。别名、锚点、重复键和不可解析内容保守保留。JSON 路径只作为代码内部数据映射及已有结构说明使用，不新增模型路径清单。


模板生成按逻辑父子关系组织阅读顺序，保留物理表和 layout 身份。隐藏内部物理列由目标 SP 版本
门控；无法确认版本时报告降级。可空字段的表示由 schema/layout 明确声明，codec 与 writer 共用
该编码契约。运行时以来源明确的业务提交和只读前端通知分别处理同名事件，窗口发现由
`runtime-windows.js` 管理缓存与失效，细节见[运行时契约](runtime.md)。

`convert` 完成输入解析与 `transformCard` 分析，`packageConversion` 负责 JSON/PNG、模板、报告和桥文件装配。核心用 WeakMap 保存每个结果对应的原始输入快照、规则选项、桥配置与模板/提示词指纹，不写入角色卡或扩展设置。

`packageConversion` 对没有 `data` 的旧式输入只在下载文件上增加 v3 `spec/spec_version/data` 外壳；JSON 和 PNG 共用这份文件数据。`result.card` 仍是转换后的原结构，供刷新和直接保存流程使用。已有 v3 输入保留外壳，不重复包装。下载文件把 `character_book` 和 `extensions` 放在 v3 `data` 下，供识别该格式的宿主导入；宿主是否运行这些脚本仍须分别验收。

UI 应用配置、合并模板和刷新下载调用 `refreshConversion`：转换规则一致时复用 schema 和已转换卡，更新模板条目、桥、templateUid 与文件；仅新增/变更的 sourceData 迁移提示词。原模板表对象引用保持不变，避免刷新后编辑器写入失效；卡片产物另行复制。模板和格式未变时复用整个结果；仅格式/报告变化只重新打包文件。规则选项变化从原始快照完整转换，不能把已转换卡当输入再次转换。

基准入口：`node test/benchmark-refresh.js [原卡.json或.png]`。默认30表合成卡，预热2轮后统计9轮中位数；比较完整转换、参数刷新和无改动刷新，不把 Node 耗时当作浏览器帧耗时保证。

`convert()` 读取角色卡、世界书、问候语、正则脚本和酒馆助手脚本，然后生成：

1. SP·数据库模板（`mate + sheet_*`）。
2. `extensions.mvu2shujuku.layout` 布局元数据。
3. 轻量卡内登记桥及扩展安装 Mvu shim 所需的元数据。
4. 内联的 `__ACU_TEMPLATE_DATA__` 模板数据。
5. 改写后的 EJS/前端数据入口。
6. 转换报告和需人工处理清单。

数据库结构名与 MVU 逻辑路径分层处理：表名中的 `{{user}}` / `<user>` 在转换时静态规范化为 `user`，但 layout 持久化时保留原 MVU 逻辑路径。运行时必须克隆 layout，再使用 SillyTavern `substituteParams` 解析逻辑组名、列路径、写路径和镜像路径；不得改写物理表名，也不得将解析结果回写到卡内 layout。

UI 层的转换配置只保存用户决策，不保存整份生成模板：同名表的 `updateConfig` 参数、`exportConfig.injectIntoWorldbook` 布尔值，以及外部表的来源值、来源内 UID、表名和结构指纹。应用配置时先从新卡重新生成基础模板，再从原来源读取外部表最新版，最后再次覆盖表格设置。旧配置缺少注入字段时不覆盖新模板的原值。不得用旧转换模板覆盖新卡结构，也不得把单表 UID 当作跨来源的全局身份。

`result-view.js` 是由真实运行时调用并内联进构建的结果视图工厂：优先显示结构化报告的人工项/警告，完整文本保留；表格列表按 UID 选择，可对所选或全部表应用参数和世界书注入设置。修改只写本次模板，通过既有刷新路径进入下载卡/模板/桥，不调用活动聊天的写库 API。报告和表名使用文本节点，不能执行作者提供的 HTML。

卡内 `extensions.mvu2shujuku.layout` 和模板定义转换时的物理结构及逻辑路径，薄桥仅登记，扩展中的 codec/writer 执行读写。`bridgeVersion` 是转换来源标记，并非自动 schema 迁移协议；新扩展保留已识别旧布局的处理分支，以继续运行已有转换卡。结构升级仍需重新转换原卡、使用匹配模板建立新聊天，旧聊天不自动迁移。

世界书整条删除必须有明确的初始化、结构规则或写入/输出管道证据。变量读取宏
`format_message_variable`、`get_message_variable` 与 `getvar(stat_data...)` 只触发数据源改写，不能作为
删除证据；comment 中的 `[mvu_update]` 也不能单独证明正文可删。

规则解析与完整文档判定共用同一份 YAML 预处理。`check` 中完整单行的自然语言操作说明
（如 `本轮减1（op: delta, value: -1）`）按字符串解析，避免其中的冒号被误当嵌套映射；
业务正文保持原样。已引用字符串、块文本、带续行的内容和其他 YAML 错误不作猜测修复，
有其他解析错误或混合 EJS 时仍保留原条目并报告。
静态 YAML 可解析也不能单独证明规则已迁移；删除前核对业务 `check`/`note` 是否进入生成表的规则。无法定位的约定保留在原世界书条目并报告，避免只因语法合法而丢失业务要求。

解析阶段记录原 YAML 节点路径及有限绑定展开后的目标路径，生成 `note` 时记录实际发出的规则；拆分同时核对来源、所属路径及最终模板说明。只读/私有列被过滤、调用方自定义模板没有承接时，原规则继续保留。凭证是本次转换的临时数据，不写入卡或模板。提醒数组按明确的组名/路径逐项拆分，未知标题、未知元字段及共享 YAML 节点保留；不根据全局分组名猜测承接方式。

当前状态快照属于模型输入，不属于模型更新输出。v0.7.0 保留状态标签内外说明及读取宏；只有专用条目中其余文本可确认为独立旧更新协议时才拆除协议，状态块本身保留。含状态展示的混合条目不交给整条旧输出删除判断，避免丢失模型所需的当前状态与业务说明。

完整输出文档先提取 `valid_paths` 等路径定义中的业务用途、条件和只读要求，再删除旧输出协议。业务定义只有在目标表的最终说明中得到承接才移除；未知路径或无法拆解的内容独立保留并报告。

`valid_paths` 等字段名是支持的作者约定，不是 MVU 标准。未知补充字段不会套用这些字段的含义，也不能因条目属于“输出格式”而删除；移除可确认的格式块后保留补充内容，并注明旧输出语法由数据库填表协议接管。若解析或拆分失败，保留原条目，不能退回整条删除。

静态规则共用完整外壳解析：支持无属性的成对自定义标签、常见文本代码围栏及有限嵌套；拒绝执行标签、相邻片段、动态 EJS 和不完整外壳。自然语言条目按已知逻辑路径归属，不能定位的段落保留；部分迁移后恢复原包裹形式。作者的标签只组织文本，不代表可执行规则。

模板说明沿用 DDL 和列说明，不额外复制逐表原路径、类型或来源引用。原路径映射记录在报告中；普通业务规则绑定到实际布局列，JSON 内部路径相对于实际 JSON 列。无法绑定或与 Schema 类型冲突的声明保留并报告。原文明确声明的只读路径作为模型更新约束；`_` 前缀不产生权限，`$` 按原默认展示过滤，不是硬写锁。不阻止原脚本通过 MVU API 写入；嵌套 JSON 的单个只读字段不会锁住整个 JSON 列。只读识别接受完整的 `readonly` / `只读` 及明确用途括注，布尔值、条件式、表达式和续行不作为自动权限依据；已定位路径的完整说明仍迁入模板，且不能因此自动开放 JSON。只读祖先与明确可写后代冲突时保留原说明。整表只读的新模板默认 `updateFrequency: 0`，部分只读及仅禁止新增/删除的单例表不适用。

完整输出文档中的 `rule` / `rules` / `规则` / `输出规则` 数组逐项识别已支持的纯输出语法；只有完整命令形态及操作描述才清理，标签命中、未知续句或业务条件不能成为删除依据。

正文条目分流由 `extension-runtime:createWorldbookRequestFilter` 工厂负责，运行时与 VM 回归共用同一实现。它在 `worldinfo_entries_loaded` 中同步读取当前角色标记与主世界书名称，仅从本次四类 lore 列表移除该书的纯更新标记条目；剧情/共享标记及其他来源保留。原世界书条目状态与内容不变，DB 填表自行读取原条目后组装请求。

异步转换复用一次解码的角色卡。保存头像仅移除 PNG 中的 `chara`、`ccv3` 卡数据块，保留图像和其他元数据；完整转换数据仍单独写入角色卡。转换与保存共用操作锁和进度弹窗，成功或失败均恢复按钮，保存结束仍须读回确认脚本数据。

插件保存还先调用 `worldbook-save.js` 的 `prepare/commit`：卡副本对齐内嵌书名与绑定，现有书完整内容相同则复用，不同则由用户决定覆盖、另存或取消，可选下载完整原生书 JSON 备份（默认关闭）。`worldbook-storage.js` 委派宿主转换格式，并检查直接读写接口及持久化内容；之后更新世界书缓存与事件。世界书与角色创建没有共同事务，不自动删除旧书或回滚不确定的写入。此链不接管下载导入，旧聊天布局也不自动迁移。

前端字段补充扫描由 `src/status-usage.js` 独立负责，构建时内联同一工厂。先提取 HTML/Markdown
前端中的脚本或 EJS，再按来源、可识别的词法作用域和声明追踪数据别名；兄弟函数、其他脚本、
参数及局部声明不继承碰巧同名的别名。普通字符串、注释、CSS 与展示文字不作为 JS 字段访问证据。
`get/list/val` 辅助读取与 `Object.entries` 回调也使用同一绑定表，只绑定实际声明的条目参数，
不把名字恰为 `data` 的无关变量当作条目；回调闭包、参数遮蔽、重新赋值和嵌套对象遵守相同边界。
这是静态补充扫描，不执行任意前端代码或外部 import；无法推导的动态结构继续依赖声明、初始数据
及既有扩展数据读写机制，不按字段名黑名单或压缩代码体积过滤。

## 模块职责与装配

转换核心 `mvu2shujuku.js` 负责转换协调和产物装配；布局推导、表格编解码、差量写入分别由
`schema-layout.js`、`table-codec.js`、`table-writer.js` 承担。运行时入口
`extension-runtime.js` 负责宿主连接、会话和事件调度。
写入模块以每次调用的结果报告成功状态、计划差异数量和失败原因；运行时据此重试或拒绝候选。
旧数字接口仅用于兼容，不参与新调用的结果判断；保存和回放仍由 SP 负责。
`runtime-globals.js` 管理窗口原始接口的登记、还原与引用释放；窗口发现仍由 `runtime-windows.js` 负责。

`mvu-commands.js` 独立处理既有 MVU 兼容入口的命令解析、命令信息转换，以及对传入内存对象的
修改。它不读取宿主、不持久化数据，也不发送事件；JSON 修复库通过 `getMvuYamlLibs` 显式注入。
运行时继续负责逐条命令的事件顺序、业务监听器和后续提交，因此提取模块不改变填表方式或卡片布局。
公共 MVU getter/setter 的路径规则仍与文本命令分开处理。

`table-prompts.js` 集中生成表格 note、初始化说明和增删改提示，包括字段说明、更新提醒、
规则措辞与安全 SQL 示例。转换核心仅保留三个薄转发，模板生成和 VWD 插槽规划均调用同一工厂。
组说明、列可见性、关系键、SQL 引号转义、Schema 示例与 VWD token 由核心明确注入；
DDL、布局推导及编解码规则继续由各自模块负责，不在提示模块复制一份。

`conversion-profiles.js` 负责转换配置的保存数据、匹配统计和外部表合并规划，返回候选模板、
来源引用和确认标记。来源读取由运行时注入；弹窗、配置持久化及界面状态不进入数据模块。
运行时在用户确认后接收候选结果，拒绝时返回本次基础模板；手动合表的来源引用仍在产物刷新
成功后才提交。配置格式保持 version 1，表格设置通过结果视图已有的 capture/apply 方法处理。

`assembleExtension` 用有序工厂清单生成浏览器注册语句；各工厂仍由相同的 Node 模块提供，并在
运行时启动前注册完毕。拼音字典、YAML 和 JSON 修复资源保留各自的装载位置。工厂必须能通过
`toString()` 在没有 Node 外部作用域的环境运行，依赖只能由参数或函数内部提供。

## 卡内数据桥

转换卡自带的 TavernHelper 脚本在正常环境中只作为卡级注册桥：携带模板、layout、卡标识和能力需求，通过 `window.__mvu2shujukuRuntime.registerCard(...)` 交给扩展。扩展确认接管后，桥立即退出，不再安装自己的 Mvu、事件或写库状态机。

新生成脚本不再携带旧运行时。扩展未加载时每秒重试登记，约十秒后显示安装或启用扩展的提示；登记异常显示失败提示并重试，拒绝登记则停止。iframe 卸载及重复执行会清理旧定时器和提示。登记成功表示 payload 已接收，不代表初始化与持久化已经完成。转换卡需要 MVU转数据库扩展运行。

历史桥兼容用例使用冻结的 `test/legacy/bridge-v0.3.17.js`，新桥用例直接执行本次转换产物。表格投影和写入仅由扩展的共用 codec/writer 执行。

历史 v0.3.15–v0.3.17 桥通过 `createBridgeLifecycle` 管理定时器、自己的事件订阅及 API 调用，向宿主登记退出控制器。扩展创建注册表时同步停止这些桥，取消尚未提交的快照并结算 false，清理监听与全局入口；等待已发出的 API 和写批次 finally 结束后才执行 main。等待期间新薄桥仍可登记 payload，不启动兼容状态机。支持 unregister 的 SP 回调会解绑，不支持解绑的旧宿主回调通过停止守卫失效。这些历史桥在未被接管时仍有旧兼容事件流程；扩展接管后仅扩展运行时活动。此前已生成的桥没有退出协议，需要重新转换，不能宣称旧脚本能被自动排空。已发出的调用不回滚；若宿主调用一直不结束，扩展接管会等待，不超时强行并发启动。

卡内桥随角色卡嵌入，无需另行导入酒馆助手脚本包。

## 脚本保留与删除边界

只自动删除：

- 已知、路径可确认的 MagVarUpdate / MVU-offline 引擎 bundle。
- 启用注册 Schema 经隔离 JavaScript/Zod 构造后读取实际对象；无导入的纯声明仍沿用移除策略；可接入的本地 Schema 保留。远程模块在转换阶段通过 `convertWithRemoteSchemas` 下载分析；已核对的 `mvu_zod` 登记路径由助手脚本中的适配器接入数据桥，默认保留外部模块。下载正文不进入插件或卡片，卡片仅保存链接、指纹和接入元数据；显式本地化选项只影响转换卡。无法下载或登记接口不支持时明确失败，不宣称完整兼容。

必须保留：

- 调用 `Mvu.*`、`getVariables`、`updateVariablesWith` 的用户业务脚本。
- 用户自己的定时器、开局、倒计时、前端和事件处理脚本。
- 保存到 SillyTavern 后，酒馆助手可能在角色创建事件后回写旧脚本面板快照。保存流程必须先刷新角色列表，再用 `extensions.mvu2shujuku.convertedAt` 精确确认新卡，通过 ST 官方 `writeExtensionField(characterId, 'tavern_helper', value)` 重申最终脚本。不得只按角色名覆盖，也不直接修改其他角色。 字段同步之后还须按创建接口返回的头像读取完整卡，校验转换标记及 `tavern_helper` 数据；接口调用完成本身不证明已落盘。列表暂未同步或缺少字段接口时，可以按唯一头像只读复核，读回一致即确认保存成功。读取失败、标记不符和脚本差异分别报告；没有唯一身份时不猜测目标。
- 无法离线证明是引擎的未知 import。
- 仅负责隐藏 `<UpdateVariable>` / `<initvar>` 的空替换正则。
- 仅名称含“完整变量”等字样、内容没有 MVU 输出证据的普通正则。

未知脚本应进入转换报告，不能为了“接管完整”冒险删除。
输入按内容识别 PNG 与 UTF-8 JSON（含 BOM）。转换结果保存源格式和源角色头像；刷新、合并和保存保留该身份。保存前刷新失败直接中止；进入异步保存后使用捕获的结果，避免 UI 切换导致卡、模板和头像串用。数据桥下载读取 JS 文件产物。

正则仅删除替换体整体为纯旧快照宏的规则，匹配目标、MVU API 与控件不作为删除证据；保留前端的格式化宏接入数据库入口。世界书删除要求完整静态规则文档或明确的输出专名/纯快照形态；业务 EJS、非专名混合内容及解析失败的规则保留并报告。`protectFrontendEjsLiterals` 只处理 script 内已知的 EJS 标签检测正则；转换时处理卡内正则，扩展在每次 `prompt_template_prepare` 的 render 上下文注册临时 HTML 正则以处理动态加载内容。回调检查当前转换卡和聊天身份，普通卡、生成阶段及过期会话不处理；不修改楼层原文或远端资源。


## EJS 与宏

- SillyTavern 宏（如 `<user>`、`{{user}}`）必须调用当前上下文的原生宏替换接口，不把原始宏字面量写入表格。
- MVU/TH `{{format_message_variable::路径}}` 必须改为 EJS 惰性数据库读取：标量输出本值，对象/数组输出 YAML，递归排除 `$` 前缀键。此规则同时用于世界书正文与表格 `note/check`。
- EJS/宏读取顺序必须与前端一致：待写快照 > SP 已提交回调 > 完整运行时表 > 持久化帧 > 结构骨架。不得无条件优先使用 checkpoint；持久化帧缓存键必须包含内容指纹，不能只用 JSON 长度。
- 表格 `sourceData` 不经过普通世界书处理链。规则中的只读宏需改为 EJS 惰性调用；`promptOnly + WORLD_INFO` 静态查找正则需迁移成运行时 helper，并继续读取原正则的启用状态。
- 正则 replacement 中的 `{{random...}}`、`{{getvar...}}` 等仍在每次生成请求时调用原生 `substituteParams`，不得在转换时求值并冻结。
- 只替换初始值字符串和动态业务键，不改写固定 schema 组名/列名。
- EJS 默认保留 JavaScript 控制流，只将可识别的 MVU `stat_data` 读取改为 `mvu2shujukuGetAllVariables().stat_data`。
- 调用改写先遮蔽字符串、注释与正则字面量；模板字符串只改写 `${...}` 内的真实代码，保留静态文本。
- 旧前端若直读 `getChatMessages(...)[0].data.stat_data`，运行时在消息浅副本上投影数据库当前状态。不修改宿主消息对象，同步/异步 `getChatMessages` 均须兼容，切卡时必须还原原函数。
- 消息副本同时投影 `stat_data` 与 `display_data`：很多旧状态栏优先使用 `display_data || stat_data`，而空对象也是 truthy。对只在 DOMContentLoaded 执行一次 `await getChatMessages` 的内联状态栏，转换时在首次读取前等待带转换器标记的投影 shim。
- EJS 输出标量（如 `<%- data.字段 || '默认值' %>`）只在原世界书渲染时有意义，不得参与静态 `enum` / `range` / DDL / 表格 note 推导。否则 JS 局部变量会离开原 EJS 作用域并在填表阶段报错。
- `getvar/setvar` 与消息别名保持原调用，由实际 EJS 上下文选择存储后端；不得展开为连续属性访问或根据静态字面量猜选项。缺失中间路径通过 Lodash/defaults 处理，局部同名函数由原 JavaScript 词法作用域处理。
- `mvu2shujukuGetAllVariables` 与 `mvu2shujukuFormatMessageVariable` 通过 `EjsTemplate.defines` 注册；不依赖页面全局变量自动穿透严格 EJS 沙箱。
- 填表插件会对组装后的整份提示单独调用 `evalTemplate`；任意 EJS 错误都会使它回退到整份原文。因此转换器 helper 既要注册到同源窗口的 `defines`，也要在 `prompt_template_prepare` 事件中注入实际上下文；对包含转换器 helper 但未传 context 的直接调用，还要通过受限的 `evalTemplate` 桥显式执行 `prepareContext`。转换卡的原生变量调用同样需要上下文适配；普通卡模板原样委派。
- 只有开启实验选项且能证明为单字段简单条件时，才翻译为数据库 `<if db>`。动态路径、循环、异步、副作用和复合分支一律保留 EJS。

完整 JSON 容器选项在规则推导后由 `schema-layout.js:preserveJsonContainers` 合并同一顶层容器的表；
它复用已有完整 JSON 布局/编解码，不增加另一套状态存储。界面显式选择，Node `jsonContainers` 可
按顶层组名限定范围。逻辑数据和原路径规则保留，物理子表及其关联定位提示不再生成。

### 转换阶段的 Schema 执行

`schema-execution.js` 是生产共用工厂：Acorn 解析词法作用域、登记调用及其依赖，实际 JavaScript 和固定 Zod 4.4.3 构造 Schema。依赖切片不启动无关界面或事件业务；它仍有登记形式和外部依赖边界，不承诺执行任意整卡应用。

`analyzeScript` 复用该 AST 的来源和作用域信息，供转换阶段决定登记调用接入与纯引擎加载器清理。它识别命名导入别名、命名空间成员及字面量动态导入的解构／赋值；同名局部函数不视为登记。回退加载器只接受已知引擎导入、简单短延时和失败诊断，混有业务或未知地址时保留并报告。大资源脚本的字段回调扫描使用保持偏移的字面量遮罩，不将内嵌资源作为代码匹配。

Node 适配器在限时 Worker 内使用独立 VM，禁止动态代码生成，不注入进程或文件系统 API；浏览器适配器通过 opaque-origin sandbox iframe 创建可终止 Worker，CSP 禁止网络连接。两者执行同一工厂。静态构造可以使用已提供的 Zod、Lodash、克隆与 JSON 修复依赖；未知必要导入明确中止。禁用声明仍只作辅助结构参考，旧文本解析器不是启用注册 Schema 的权威。

转换只读取对象结构，不为猜测类型调用任意 transform、refine 或函数默认值。时间/随机值等环境依赖不被冻结为未来开局初值。未知值结构完整 JSON 保存并报告；字段名或必要根结构不确定时中止。运行时仍由原脚本登记实际 Schema，转换执行环境不参与每次状态栏刷新。

Zod walker 从实际数值对象的格式／倍数元数据保留整数契约；MVU 的普通 number 不推断为整数。`buildSchema` 合并声明和路径规则后统一选择标量 SQL 类型；嵌套数组与动态标量记录共用类型选择，混合元素复用 `jsonScalar` 的实际读写协议。物理列声明与原 Schema 的运行时校验分别负责存储表示和业务约束，见[数据模型](data-model.md#标量类型)。

## 当前状态迁移的边界

统一状态树是跨存储的交换格式。状态导入导出复用原生消息变量 API、现有表格编码／写入和数据库提交，不引入第二套运行存档、SQL 回放或作者规则解释器。额外表格是可选附加数据，普通与转换目标均可匹配已有定义。完整聊天 JSONL 只作为覆盖前可恢复备份，不作为插件额外运行时真值。

显示过滤与写入权限分别处理：原格式化宏递归过滤 `$` 当前值，MVU 更新接口仍可接受其路径。转换器按 Schema／InitVar 保留声明字段的数据库写入位置，保留作者更新要求，不凭隐藏前缀或自然语言推测字段由脚本专属维护。
