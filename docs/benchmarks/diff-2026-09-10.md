# 差异写入基准（2026-09-10）

命令：`node test/benchmark-diff.js`。Node v18.20.4，单次预热后各测一次；内存宿主直接修改数组，不包含网络、SQLite、插件事件和酒馆保存耗时。该结果用于检查规划成本和 API 次数，不代表真实聊天的端到端耗时。

| 变更记录数 | 每行变更字段 | CPU / ms | updateCell | updateRow |
| ---: | ---: | ---: | ---: | ---: |
| 100 | 1 | 0.80 | 100 | 0 |
| 100 | 3 | 2.55 | 0 | 100 |
| 1000 | 1 | 9.79 | 1000 | 0 |
| 1000 | 3 | 19.33 | 0 | 1000 |
| 10000 | 1 | 79.73 | 10000 | 0 |
| 10000 | 3 | 151.85 | 0 | 10000 |

按表和键列复用规划阶段的行索引；同行多字段合并为一次 updateRow。执行阶段重新定位实际行，避免插入/删除后继续使用旧行号。API 次数随变更记录数增长，没有为每个字段重复提交整行。

数组不在这项 CPU 场景内：`test/array-writer.js` 单独覆盖无差异零写入、单操作原生 CRUD、多操作一次导入、失败后按实际快照重试、父级隔离及行标识保留。批量导入依赖 SP 的原子持久化接口，不把混合标量写入描述成全批事务。
