# 数据映射与规则

[文档索引](README.md) · [开发验证](development.md)

本文描述当前有效实现；兼容承诺以[兼容清单](../COMPATIBILITY.md)为准。文中的仓库路径均相对仓库根目录。

## 数据结构转换

建表前必须先按对应版本 MVU 上游 `schema.ts` 的初始化顺序分析 `$meta`、`$arrayMeta` 和
`$__META_EXTENSIBLE__$`，再执行与 `cleanUpMetadata` 等价的清理。元数据只提供固定/开放对象、
递归开放、必需键和动态条目模板的结构证据，绝不能成为业务列或表。多开场分支的开放性按并集
推导；`template` 只作为空动态容器的条目样本，不得作为实际初始行写入。

### 固定对象

键集能从 InitVar、type、Zod 或明确规则确定的对象展开为固定列。嵌套列名使用 `_` 分隔，例如 `人口_宗主`。

布局中保存权威逻辑路径；读写时根据布局映射，不从显示列名反猜路径。

单例中的附属对象有明确固定 Zod 声明时，不再因为其子对象拥有相同字段就误判为条目字典。
固定字段并回父表列，完整逻辑路径保持不变；各路径的数值范围、枚举、布尔类型、描述及
`_` 只读/`$` 隐藏语义继续保留。动态后代和数组仍独立提取，不按当前条目数猜测是否合表。
仅有 InitVar 样本、没有固定声明的条目字典沿用原推导；已有聊天不自动调整布局。

### 动态字典和关系子表

- 顶层动态字典转换为行表。若 `type` 索引签名声明 `[物品名称: string]`，使用「物品名称」作为业务键列名；无可靠声明时回退为「键名」，与 value 字段重名时自动消歧。
- 动态行的字段集以 type/Zod 中的条目 value 对象本层为准；嵌套背包、装备、技能等子对象的叶子不得误提升到父行表。
- 行条目内的字典/数组转换为关系子表，如 `角色_技能表`。
- 关系子表通过 `角色_键名` 一类关联列归属到原条目。
- 两层以上的动态关系保存完整祖先键链；例如 `关系列表.NPC.背包.物品.效果` 使用
  `关系列表_键名 + 背包_键名 + 键名` 联合定位，不能只凭同名物品键归属。
- 集合整体规则放在关系表；只有自由提醒且无法安全定位到集合路径时，才保留在原表。
- 固定容器本身不落表、数据由其动态子表承载时，容器级 `check` 按完整逻辑路径前缀传播到这些子表；不得按表名或业务关键词猜测。
- 迁移到表格 note 的 MVU/JSON Patch 操作词转换为存储语义：JSON 列描述为定位并修改目标元素、保留其他内容，独立行表描述为新增、更新或移除记录。双模式 note 明确区分 SQL 路径更新和 native 整格写回，具体输出格式由 SP 当前模式决定。

「关联列」是语义上的外键，但当前不生成 SQLite `FOREIGN KEY`：插入、初始化和重放顺序由插件管线管理，强制物理外键会增加时序失败风险。

面向填表模型统一称为「关联字段」，直接说明实际列名及其对应的表和字段；定位时列出必须同时
匹配的所有字段，包括本条记录的标识。提示词不混用父键、祖先键、关系键或父表/子表等结构术语，
而以实际表名说明数据归属及同步删除、标识值变更要求。联动明确由本次填表完成，不暗示自动级联。
内部 layout 仍使用原有 `parentKeyCol` / `ancestorKeyCols` 等属性，不改物理列名或读写契约。

### 数组

顶层或嵌套数组优先转换为有序行表。数组允许重复元素，不得把值误当成唯一业务键。
顶层数组的新布局携带 `valueCol` 和 `jsonScalar` 列类型，单元格按 JSON 编码保留字符串、数字、布尔、null、对象和数组。缺少类型信息的旧数组布局仍按文本读取，不猜测旧字符串类型。

### 混合标量字典

同一动态字典同时包含字符串、数字、布尔或 `null` 时，值列使用 `jsonScalar` 逻辑类型，表中存
`JSON.stringify` 结果，反投影时再解析。不得统一 `String()`，否则数值和布尔会发生不可逆类型退化。

### 可空普通列

新转换时，单例、动态行和嵌套关系行中已出现 `null` 样本，或 Zod 明确声明
`nullable()` / `optional()` / `nullish()` 的普通叶子列使用
`jsonScalarOptional` 布局类型，物理列为 TEXT。只对这些列采用以下编码：

| MVU 值 | 单元格内容 |
| --- | --- |
| `null` | `null` |
| 空字符串 | `""` |
| 字符串 `null` | `"null"` |
| 数字 / 布尔 | `0`、`1.5`、`false` 等 JSON 字面量 |
| 缺失字段 | 空单元格，读回时省略该键 |

脚本更新、新行插入和删除该列对应叶子均使用相同编码。布局保留初始 `null` fallback，
供整表尚未加载时读取；已有表内的空格子不回填 fallback。非标量和非有限数字写入返回失败。
SQLite CHECK 校验合法 JSON 标量，并对解码值执行已有范围/枚举约束；编码说明每表合并一次。
native 仍依赖模型遵守填值规则，非法裸文本不猜成业务字符串。

有 null 样本的 VWD 标量列使用 `jsonPairOptional`：单元格仅编码当前值，读回恢复
`[值, 布局描述]`，不把 null 变成空串。描述仍是静态列元数据，不承诺逐行动态修改描述。
公共 getter/setter 的 VWD 判定与表格布局推导是不同层次，普通数组不受此编码影响。

#### pair 叶子的写库边界（与 VWD 开关无关）

脚本写回的整段 `[当前值, 说明]` 叶子在写库前按 **layout 明确登记的路径**取出当前值：
登记来源是列类型为 `pair` / `jsonPairOptional`，以及被 `columnLayoutType` 映射为
`number` / `boolean` 但仍带 pair 标记的标量化列。取出的值再按该列真实物理类型编码：
`jsonPairOptional` 沿用 JSON 标量编码，保留显式 `null` 与缺失的区分；数字保留数值，
布尔编码为物理值 `0` / `1`，文本 pair 写标量文本。普通非 JSON 列的空值沿用列默认值。
SP native CRUD 直接保存传入值，不能依赖宿主替插件归一化布尔值。新增行从保留的原始值
取出 pair 当前值，再生成物理行，避免先转成逗号拼接文本后丢失结构。

这条规则是编码契约而不是可选功能：宿主单元格只接受字符串/数字，SP 的 SyncBridge 对数组调用
`.replace` 会抛错，导致 SQLite hydrate 失败（`val.replace is not a function`）并静默回退原生。
写库边界统一编码一次，`updateRow` / `updateCell` / `insertRow` / `importTableAsJson` 都取自同一结果。
普通数组与对象列不参与拆分：`jsonScalar` 数组元素保持既有编码，JSON 对象列按键更新。
编码后再次检查已有 pair 单元格是否实际变化；相同当前值不随其它字段重复写入。新增行和动态说明附带的原子写入保留。

### 完整 JSON 容器选项

转换前勾选「将容器保存为完整 JSON」，或 Node 调用传 `jsonContainers: true`。
Node 也可传顶层组名数组，按组选择；默认表格映射不变。选中的初始对象/数组各保留一列「内容」，
原先的子表合并回 JSON，使用已有 singleton/valueCol/jsonObjectOptional 编解码。
缺失、null、空对象/数组与有值直接由数据表示，无额外状态列。

合并发生在原有字段和规则推导之后，按 layout 的完整路径保留说明、格式、检查及约束。
固定数值/小枚举仍可生成 JSON CHECK，pair 当前值用数值路径段 0 表示数组下标；动态元素约束
保留提示并报告 SQL 限制。pair 的当前说明直接随 JSON 保存，因此动态记录、数组与对象值中的
说明无需单独登记或固定 note 渲染。普通拆分布局仍遵守后面的 VWD 登记范围。

SQLite 可以按路径更新；native 需更新整个单元格。混合 JSON 内部的私有叶子不能分别隐藏，
转换报告沿用既有警告。该模式和旧聊天迁移不同，见[范围与验收](validation/2026-09-22-full-json-containers.md)。

### VWD 动态说明

新渲染路径由转换选项 `vwdDescriptions: true` 登记，UI 按 EJS 桥能力自动选择；目标 SP 须支持隐藏列。
Node 核心默认不登记，旧 `vwdExperimental` 入口仍关闭。旧布局不自动迁移。

单例表中 layout 类型已确定为 `pair` / `jsonPairOptional` 的字段，以及新动态说明布局中
带 pair 标记的 number/boolean 字段，会共用一列隐藏 JSON 元数据列（默认 `$说明覆盖`，与作者字段撞名时统一消歧并改名）。该列的写入格式是
`{"v":1,"o":{"<字段身份>":"<说明>"}}`：字段身份是 layout 登记路径数组的 JSON 串
（`JSON.stringify(path)`），不使用易重名的显示列名，也不做点分拼接转义；`o` 只保存与静态
默认不同的说明，显式 `""` 是有效覆盖，未登记键一律忽略。读回时“当前说明 = 覆盖 → 静态默认”，
值为 null 与整个可选字段缺失仍按既有语义区分。新布局的数字/布尔字段保留原物理类型，
读回恢复 `[值, 当前说明]`；默认静态转换和旧实验布局不改变原有标量形状。可解析且版本受支持的覆盖集合按键回退：
合法字符串项生效，非字符串项和未登记键忽略；无效 JSON 或不支持的版本则使整个集合回退。

note 由**逐字段插槽计划**驱动，`promptVersion: 1` 表示请求时动态渲染。`plan` 保留字段 token，
`noteTemplate` 保存原规则/宏迁移后的完整固定模板。note 前导 EJS 一次读取该表所有说明，
各字段插槽只输出自己的当前说明；相同原文不串字段，初始空说明也预留位置。原规则与宏继续
在原位置执行，不把整段 note 当作说明转义。字段身份和内部 token 不进入模型请求。

普通说明原样输出；含 `<>{}$&` 或控制字符等内容使用明确标注的 JSON 字符串，特殊字符用
Unicode 转义，避免 EJS、酒馆宏及 SP 查询/条件/随机模板再次解释。该表示可逆，存储和读回
不使用转义后的文本。可能增加此类说明的 token 数，不能声称任意文本零成本。

写入前检查 EJS 桥、元数据列和完整固定模板是否匹配；旧静态实验布局仍拒绝说明变化。
候选工厂保留新渲染布局的原始 pair，交给同一 writer 编码；值和覆盖集合通过既有批次提交。
纯值写入不清除已有说明；未变化说明不产生元数据写入。旧实验布局仍保留原折叠/拒绝路径。

字段级 Zod 可空对象/数组使用 `jsonObjectOptional`，保持一个 JSON 列，允许容器、
JSON null 或缺失；空对象、空数组与缺失不混同。新行未提供的字段留空，不复制样本行的值。
layout 第 7 项记录无默认值标记，第 8 项记录 object/array 种类；旧前 6 项不变。
带 VWD 字段的单例表在条目上多一个可选的 `vwd` 槽位（`{v, metaCol, fields, tokens, plan, noteTemplate, promptVersion?}`），
没有 VWD 字段的表不产生该键，旧读者忽略即可。
写入前递归检查纯 JSON 值，拒绝非有限数字、undefined 子值、数组空洞、循环和 Date/类实例，
跨 iframe 的普通对象可写；SQLite 同时检查声明容器种类。
明确声明 nullable/optional/nullish 的顶层对象、数组、字典使用单例完整容器列：布局的
`valueCol` 指向唯一 JSON 列，读回直接还原整个组。空单元格省略顶层键，JSON null、空对象、
空数组保持区别；初始缺失也建表，但缺表窗口不造默认对象。固定内部路径的范围与小枚举可用
SQLite CHECK 检查，动态元素约束仅保留说明并报告限制。见[整组空值验收](validation/2026-09-16-container-presence.md)。
明确声明可空对象/数组值的动态字典，使用身份列加完整 JSON 内容列，布局复用
`scalarValueCol` 与 `jsonObjectOptional`。覆盖根字典、单例内字典和多层关联；内部字段不再
派生重复子表。JSON null、空容器与删除记录各有独立表示，空单元格也读回为缺失键。
说明与规则保留在内容列；固定路径 CHECK 接受所有初始记录的哨兵值。关联的插入重放守卫
与读写定位共用完整祖先键。见[可空动态记录验收](validation/2026-09-21-nullable-records.md)。
未声明的拆分组运行期变空仍不完整；根 stat_data 仍要求对象。

不自动迁移旧布局，也不把旧空字符串猜成 `null`。未声明可空、也没有空值样本的列，
运行中首次写 `null` 会明确拒绝，避免静默变成空字符串；应补足声明后重新转换并迁移模板。
没有 null 样本或 optional 声明的稀疏列仍沿用既有缺省行为。

新布局的普通文本列使用 `textExact`：已存在的空单元格读为 `''`，不会恢复初始文本。
旧布局的 `text` / `pair` 保留其 fallback 规则。旧聊天必须先按旧布局解码、备份，再按新布局
重新编码；不能直接替换 layout 标签，也不能从旧空格子反推已经丢失的 null/缺失意图。
旧聊天的无损原始值尚在时，可导出并备份旧 stat_data，重新转换后在新聊天通过兼容 API 写入，
核对读回再继续使用；没有原值时需要用户决定旧空值含义，不执行猜测式自动迁移。

### 关系记录生命周期

脚本差量明确删除或重命名父行时，writer 按完整祖先键递归清理后代物理行，避免读回已看不到、
表格却仍保存旧键的孤儿数据。索引按子表建立一次，同名子记录不会跨父记录误删。
省略整个父组仍是部分写入，不触发清理；历史孤儿不自动扫除。子数组清理合入数组原子计划，
其他单元格先更新再倒序删除，避免行号位移。直接在 SP 编辑表格仍依赖明确的关联操作，
本改动没有给宿主添加物理外键。

### JSON 逃生舱

JSON 只用于：

- 字段级可空/可缺失对象、数组，保留容器、null 与缺失的区别。
- 没有 schema，且样本不足以推导固定结构的对象。
- 真正无限动态的嵌套结构。
- `_` 前缀的脚本私有状态。
- 每张表的 `_扩展数据`，用于无法建列但必须保存的字段。

已有列的值始终优先于 `_扩展数据`；读回时只用扩展 JSON 补齐缺失叶子。
`_扩展数据` 与其他 `_` 前缀列共用只读提示，但仍从 AI 列定义和 INSERT/UPDATE 示例中排除。

### JSON 列的 SQL 局部更新

可写 JSON 列在 SQLite 或双模式 note 中提示 `json_set/json_replace/json_remove`：仅修改规则
允许的路径，保留其他字段。对象、数组、布尔及 JSON null 新值用 `json('...')` 保留类型；
空单元格/JSON null 容器先按原规则初始化。数组末尾追加可用 `[#]`，中间插入/移动需正确重建
受影响数组；不把 SQL `json_patch`（Merge Patch，null 删键）当作 MVU JSON Patch。

SQLite 专用 UPDATE 示例从实际 JSON 中选择一条可表示的公开叶子路径，并正确转义 SQL 字符串。
没有安全示例路径时不编造键、不用空对象覆盖原值；整组 JSON 的路径权限来自规则，不猜示例。
普通表与纯只读 JSON 表不追加这段说明。native 仍提交完整的新单元格 JSON，不增加新补丁协议。
这是模型输出方式的优化，程序与数据库内部仍可序列化完整单元格；不承诺完整请求 token 按同等比例下降。

### 通配路径

- `${角色}.好感度` 这类“动态行 + 静态字段”可展开为固定列。
- YAML 节点键 `${A|B}` 按官方模板写法展开；同时兼容已有卡片中的 `${A/B}` 以及 `${A|B}经验` 等带前后缀的合并字段。节点下的 type/check/range/format/enum 必须沿展开后的完整路径保留。
- YAML `range` 数值区间进入列范围；非数值数组按可选值枚举处理，不得在数值解析失败后静默丢弃。
- 更深层通配只在规则提供可验证的有限集时展开，如 `${A|B}`、「部位包括：胸部、腰部」或明确配对列表。
- 无有限集证据的动态键保留在行表、关系表或 `_扩展数据`，不猜测列名。

## 顶层数字

顶层有限数字使用 REAL 列、原值默认值和数值类型 CHECK。内部复用单行整组投影 `kind: json`，通过 `scalarType: number` 区分物理数值列与 JSON 列；布局序列化保留此标记，codec 按数字读取与补缺省，writer 校验有限数字并直接提交数值。其他 JSON 组和无标记的旧布局仍走原语义，不自动迁移已有聊天。

公开顶层数字与对象内数字一样，在剧情明确变化时允许 AI 更新；缺少 check 不代表归脚本所有。
`_` / `$` 前缀的顶层数字仍提示只读。未声明可写路径的整组 JSON 继续采取保守只读策略。

## 规则、约束与 AI 提示

规则解析接受 `变量更新规则` 与 `variables_update_rules` 外壳；TypeScript 纯字符串联合通过 `enumPaths` 保存完整字段路径，由 `attachFieldRules` 归属到列，不能按同名字段跨组传播。包含宽 `string` 的联合不生成枚举约束。

- 列类型、`range`、枚举和可证明的 `check` 转换为 DDL 约束。
- 不把描述文字误当枚举。出现 `string;` 或描述句被写入 `CHECK IN` 表示规则分类出错。
- 对象/数组 JSON 列保留 `json_valid` 和 `json_type` 约束；`_扩展数据` 是内部书写，不要添加不必要的 JSON CHECK。
- `_` 前缀业务字段对 AI 可见、提示只读，脚本/EJS 仍可读写；这不是 SP 物理列锁或回滚机制。
- 新模板为 `_扩展数据` 与 `$` 私有字段设置 `sourceData.hiddenPhysicalColumns`，使用 DDL 物理列名。
  关系定位键不隐藏；业务数据、DDL 与 layout 保持完整。旧聊天不会因此自动迁移。
  核心默认目标 SP 为 9.2.5；宿主转换读取已安装 SP manifest，旧版或版本未知时关闭隐藏并报告。
  JSON 内部混合的 `$` 叶子无法用物理列投影单独隐藏，转换报告会指出实际发现的边界。
- 提示词只描述 AI 需要的业务列和更新条件，不重复输出生成器内部逻辑路径；作者规则中有意义的路径与限制保留。共享 note 不自编列号，native 列号由宿主的可见列投影决定。
- native 专用模板不附带转换器生成的 SQL 示例；双模式与 SQLite 模板保留具体示例，双模式明确要求 native 填表忽略 SQL、遵循宿主原生协议。适用范围与禁止照抄示例值的说明在每张表 note 中只写一次；原业务规则、数据与 DDL 不变。
- `_强制更新提醒` 合并为“强制更新提醒（按各项触发条件执行）”标题，下列原始字段与条件逐项保留，不额外强化为每轮都必须修改。
- 关联记录用实际列名示范完整定位组合，占位值必须换成当前数据。数组分别说明 native 提示的
  0 基整表行号与 SQL 实际 row_id；来源内数组序号不能直接作为表格行标识。默认双模式保留两种
  解释，不混投两套可执行 CRUD 指令，也不新增列或外键。
- note 不再重复纯列名/拼音映射；字段业务说明、可空编码和每表守卫仍保留。
- 字段的描述、格式、范围、枚举与更新条件逐列放在「字段说明与规则」，使用实际列名；
  相同规则也不跨列折叠，避免丢失独有描述或混淆适用对象。保留多行描述和可见只读字段的含义，
  关联标识的作者自定义说明也保留。没有内容时不生成空标题，私有字段和内部溢出说明不进入提示。
- 规则清洗不因「指令」、英文操作名或括号中的路径删除业务内容。只改写可完整识别的 MVU
  机制写法，保留增量、新值、容器其余内容和数组删除条件；混合业务或含义不明的参数保留原文。
- SQLite 专用示例只演示写法，不指定本轮业务变化。INSERT 延续初始行/默认值优先，无值时按约束
  选取示范值；UPDATE 区分枚举、数字、布尔、可空值和 JSON 编码，不用通用文本覆盖这些类型。
  没有非空类型依据的可空列不猜类型；多层关联数组的示例包含全部关联字段。原有 JSON 路径示例保留。
  示例前明确要求依据当前表格、正文和规则确定实际标识与新值；不把示例正确性等同于模型质量保证。
- SP 独立填表从原始聊天正文取上下文，酒馆显示正则不会自动排除 `<initvar>`。
  开场包含该标签时转换报告会提示在 SP 标签排除规则中设置起始 `<initvar`、结束 `</initvar>`。
  此设置影响独立填表上下文；原始消息与初始化资料继续保留。混合 JSON 内部私有键仍需单独检查。
  关系子表明确完整祖先键以及删父、改父键时的同步操作；这属于填表操作要求，数据库不自动级联。
- 同一字段仅有一条约束时使用单行；多条约束以字段名为一级条目、范围/枚举/格式/check/描述为缩进子项，保持原顺序且不重复字段名。
- INSERT / UPDATE / DELETE 触发语句风格应与 所核验 SP 版本的默认表格模板（来源见[参考说明](../REFERENCES.md)） 保持一致。

表名中的 SillyTavern 宏是结构标识，不得在运行时求值。转换时去掉宏包裹符，将参数分隔符和非中英文/数字/下划线字符折叠为 `_`；例如 `{{user}}` → `user`、`{{getvar::阵营}}` → `getvar_阵营`。该规范化只作用于数据库表名及其结构引用，布局中的 MVU 逻辑路径保留原名；重名使用稳定数字后缀消歧。

## 模板表格顺序

新转换模板按可证明的逻辑父子关系作稳定的父先子后排序：优先 `parentTable`，其次父组 `childTables` 的完整表名，最后使用完整逻辑路径前缀。多个候选父组有歧义时不猜测，不按显示表名前缀或同名 `parentGroup` 归组。主组相对顺序保持稳定，派生表及其后代紧随父组。

排序只改变生成模板的表枚举顺序和 `orderNo`，不重排 schema/layout、UID、物理表名或行数据。合并外部模板继续遵循既有合并顺序；不自动迁移旧聊天的指导表顺序。排序不等同于 token 压缩，模型效果需独立测量。
