# MVU转数据库（SillyTavern 扩展）

SillyTavern 扩展，支持把 **MVU 角色卡**转换为 **龙血玄黄·数据库**（原 SP·数据库）角色卡，也可以直接在普通 MVU 卡之间迁移变量和聊天。

- **转换角色卡**。生成 SQL 表格模板、带原头像的新卡和转换报告。可以直接保存到酒馆，也可以下载 JSON／PNG。
- **导入和导出状态**。在普通 MVU 卡与转换卡之间双向迁移最新变量，普通 MVU 卡之间、转换卡之间也可互迁。兼容的额外表格可一起导入。
- **批量迁移聊天**。复制所选聊天的正文和最新状态到现有角色，也可以在保存新转换卡时一起迁移。原聊天保留。详见[聊天状态存档](#聊天状态存档)。

**v0.8.9** 优化长聊天的历史读取、游戏中的重复读表和大 PNG 转换。更新扩展并刷新即可使用，已有卡和聊天无需重转或迁移。 [更新日志](CHANGELOG.md) · [兼容清单](COMPATIBILITY.md)

## 安装

1. 在 SillyTavern 的 **Extensions 面板 → Install extension** 里粘贴本仓库链接。

   `https://github.com/wmdl2/mvu2shujuku`

2. 安装后刷新 SillyTavern，设置面板会出现「MVU转数据库」。

游玩新转换的卡需要安装 **龙血玄黄·数据库** 并在数据库设置中启用 **SQLite 模式**。作者状态栏和脚本继续使用酒馆助手，EJS 继续使用提示词模板扩展。普通 MVU 卡之间只迁移 MVU 状态时，使用原卡已有的 MVU 环境即可。涉及额外表格的导入需要数据库提供持久导入接口。

## 使用

1. 打开扩展设置面板，选择输入：当前角色卡，或文件选择器（支持 `.json` / `.png`）。
   JSON 文件支持 UTF-8 BOM；自动导出格式跟随原文件类型。世界书为空但问候语含有效 `<initvar>` 的卡也可以转换。
2. 点击转换，先查看兼容提醒和报告，再调整表格设置；需要时合并其他数据库表格。表格设置可折叠，每行会显示已设置的参数。
3. 在结果区末尾选择保存或下载：
   - **保存角色卡和模板到 SillyTavern**（转换完成后出现在结果区末尾，旁边显示是否已保存）：把角色卡写入 SillyTavern 角色列表（自动带原头像），
     并同时把表格模板存为 龙血玄黄·数据库 插件的“全局模板预设”（预设名 = 卡名 + `模板`）；
     开局进入新聊天会自动建表，无需手动切换；预设仅作备用。失败会弹窗显示日志，
     角色卡部分失败时自动回退下载。即使 SillyTavern 开启角色浅加载，也会按新卡头像取完整卡复核转换后的酒馆助手脚本；
   - 或下载 角色卡 + 表格模板 + 转换报告。另有“数据桥源码（仅供调试）” `.js` 备份；数据桥已内嵌到转换后的角色卡，无需导入，该 `.js` 也不是酒馆助手的 `.json` 导入包。

也可以把 `.json` / `.png` 文件拖到转换区选中，再点击转换。表格参数修改会随下载或保存带入产物；有未保存的表格修改时，再次转换会先确认。转换后更改 DDL CHECK、完整 JSON 容器或高级兼容选项，结果区会提示重新转换，当前结果保持原规则；角色卡、模板、数据桥和保存内容保持一致。PNG／JSON 输出格式可直接切换，无需重新转换。

插件内保存会同步转换卡的本地世界书。同名书内容不同时，可更新原世界书、另存新世界书或取消。更新会影响其他绑定该书的角色，覆盖前可选下载旧书 JSON 备份，默认关闭。另存会让新卡绑定新书。下载后的手动导入按宿主自己的流程处理。

TauriTavern 的文件导入、插件内保存和 DOM 虚拟化有各自的兼容边界。使用虚拟化时按受测配置关闭酒馆助手的流式前端渲染，并重载应用。 [角色卡导入验收](docs/validation/2026-09-27-tauritavern-card.md) · [虚拟化设置与限制](docs/validation/2026-10-04-tauritavern-mobile-virtualization.md)

> 无可用 `[InitVar]` 或 `<initvar>` 时，可以从已启用 Schema 的完整静态默认值初始化；缺少必填值、动态默认和禁用声明不会用于开局。多开场分支预建所需根组，但不合并各分支初值。远程 Schema 在转换时下载分析，默认继续由原角色脚本加载，登记给数据桥执行原校验与变换；模块内容相同时尽量固定 commit，无法固定会在报告中说明。原脚本仍须启用，外部依赖仍可能需要联网。

新转换卡的世界书包含 **`[M2SJK]填表适配说明`**。在数据库的填表世界书选择中保留它和作者的更新要求。升级扩展会继续按旧卡的布局读写。需要使用新的表格布局或填表条目时，从原卡重新转换，使用新模板和世界书建立聊天，必要时迁入旧状态。

### 查看报告与设置表格

结果页先展开「兼容性待确认」和「注意事项」：这些是转换成功后的兼容提醒，部分行为可能与原卡不同，需要按使用情况核对。普通说明、自动转换记录和完整报告可按需展开；报告内容仍可完整复制、下载。高级兼容选项和合并其他模板折叠显示。

「表格设置」支持按表名筛选、勾选多张表，再把同一个更新参数数值应用到所选表，也可逐表修改。全选和「反选当前列表」只影响当前可见行；筛选不会清除已有选择，「应用到所选」仍包含隐藏的已选表。要批量设置全部表，清空筛选后全选，再应用到所选即可。

每张表都有「注入世界书」开关，也可对所选表批量开启/关闭。它对应 龙血玄黄·数据库的「注入到世界书条目」：关闭不删除数据，不影响前端/脚本读写，也不会停用自动填表。额外索引和原卡世界书中显式读取数据的内容需单独检查，不能把它当作禁止所有模型读取的开关。

这些设置随下载/保存写入新模板，并记录在转换配置里，不自动修改已有聊天；旧配置缺少世界书注入字段时，沿用新模板本来的设置。

### 合并数据库现有表格模板
转换完成后，可在扩展面板选择 龙血玄黄·数据库 插件里的模板来源（当前聊天模板 / 全局模板 /
全局预设），加载出表列表后勾选要并入的表，点「合并到转换结果」：
选中表会并入转换结果，并同步更新角色卡内嵌模板、数据桥和报告。重名表自动跳过。保存前可在结果中移除已合并的额外表。

### 重用转换配置

应用配置、编辑模板参数或合并表格后，转换器会复用已完成的角色卡分析来更新下载和保存内容。没有改动时直接复用产物；改变转换规则时重新分析原卡。

新卡无需增加操作：下载转换后的角色卡/表格模板，或保存到 SillyTavern 时，扩展会以原角色卡名自动保存转换配置。只有已存在同名配置时才需选择替换或重命名。重新转换原卡或更新版卡时，可在「转换配置」下拉中主动选择旧配置。

外部表只记录来源（当前聊天/全局/指定全局预设）和表身份，不复制完整表。再次应用时会从来源读取最新版；来源被删除、表消失或表名冲突时会跳过并在摘要中说明。当前 龙血玄黄·数据库公开 API 没有提供内部默认模板的只读导出，因此不把它列为可选来源。

转换器会先生成新卡的基础模板再校验所选配置。正常匹配不增加操作；当大部分表对不上、外部来源不可用或有同名冲突时才弹出摘要确认。取消后本次不应用该配置，后续下载/保存也不会覆盖它。

## 聊天状态存档

扩展面板的“导出状态”保存当前选中分支的最新完整 `stat_data` 和额外表格；“导入状态”支持普通 MVU 与转换卡互导，也支持变量结构相容的不同转换布局。普通目标需要酒馆助手和已初始化的 MVU 消息／聊天变量状态，导入沿用目标原存储位置。涉及表格的导入还需要可识别的 SP·数据库 8.5 或更新版本，或龙血玄黄·数据库 1.0.0 或更新版本，以及已初始化的正确模板。

导入先显示目标聊天及额外表格匹配／跳过结果。确认导入后，插件覆盖目标原存储位置的当前状态（最新 AI 消息或已初始化的聊天变量）。弹窗中的“导入前下载完整聊天备份”可选，默认勾选；选中时先保存聊天并下载酒馆原生完整 JSONL，备份失败则不写入。新聊天可取消勾选。额外表格只导入身份、列结构和 DDL 相容的已有模板；找不到或存在歧义时跳过。目标表格说明、DDL、更新参数与未匹配表格保留。支持本插件版本化状态 JSON、普通 MVU 变量表 JSON 和裸 `stat_data` JSON。

无法完整兼容时，预览明确切换为“仅导入兼容字段”，列出可导入、跳过和目标保留的字段，确认后才写入。旧档已有的值按路径迁移，缺失项优先保留目标已有值。必要的新字段可以用可确定的目标默认值补齐，预检会列出补值。普通 MVU 与转换卡共用这一步。字段改名、数组拼接及需要执行业务函数的变换仍需另行处理。没有可安全导入的数据时停止。

该功能迁移当前状态，不迁移全段历史或外置世界书、角色脚本、全局／脚本变量。备份包含当前聊天文件的全部消息和已保存分支，但不是整个酒馆环境的备份。作者改变变量含义、路径或类型时，不猜测迁移规则；旧布局已丢失的数据也无法重建。原文件保留跳过的额外表格，便于后续重新匹配。

### 迁移到已有角色卡

在「聊天状态存档 → 迁移聊天」选择目标角色卡和来源角色卡，勾选要复制的聊天，点击「迁移所选聊天」。这一入口可以直接在普通 MVU 卡之间迁移。

普通 MVU 卡与转换卡都可作为来源或目标。普通目标在新副本用自己的开场初始化，再迁入相容的旧状态。目标新字段保留已初始化的值，确有缺项且可确定时按目标默认值补齐。

### 转换时同时迁移聊天

转换完成后，可展开“同时迁移聊天（可选）”，启用“保存后迁移所选聊天”，选择来源角色卡并多选聊天。来源卡可以与新版目标卡名称不同。点击“保存新卡并迁移所选聊天”后，先保存并核对新卡，再显示批量兼容预检；确认后，每条来源聊天分别复制成新卡下的独立聊天。成功项会清除勾选。

### 聊天迁移范围

预检分别列出每条聊天的 MVU 状态和额外表格结果，同名角色会显示各自的卡文件名。确认后复用预检阶段创建的副本。取消或切换聊天时，能核实仍为占位内容的本次副本会被清理，保留有用户修改的副本。

迁移需要刷新角色列表时，会先确认所需角色已经出现在返回名单中，再让酒馆刷新界面；异步空列表或旧名单会有限等待。等待期间取消或切换角色／聊天会停止迁移。此检查只在迁移过程中运行。

复制保留每楼当前选中的正文、时间和辅助变量；其他重roll候选留在原聊天。各聊天迁入自己的最新状态，旧MVU状态栏不逐楼转换。字段与额外表格沿用兼容检查；部分兼容、跳过项及失败项会列出。如果作者的整套变量规则无法单独校验，完整导入失败后会按目标表格映射逐组核对，无法无损保存的组保留目标值。相容的原数据库历史及已有表进度随副本保留；不能对应时，预检说明只迁移兼容内容。新聊天使用目标模板和世界书。

原聊天不打开、不改写。普通MVU源从保存的JSONL提取状态；数据库源在无作者脚本的隔离副本中通过宿主公开只读接口读取，需要数据库提供该接口。读取期间来源变化、用户切换聊天或目标保存读回不符时停止；已含正文或用户修改的失败副本保留，取消不删除已完成聊天。

检测到兼容的V2物理楼层存档和所需接口时，会为迁入MVU表建立导入覆盖基线，避免自动填表重填旧剧情；额外表进度不凭有无数据行推断。不按数据库发行版本号设白名单；未知存档格式或缺少接口时，预检说明覆盖限制。当前不支持群聊或数据库零层逻辑存档。

额外表逐表核对进度。能唯一对应的表沿用来源覆盖到的 AI 楼层。遇到结构变化，预检分别说明行数据和进度是否迁入；重填由用户在数据库中操作。

## 转换逻辑

### 表格生成
- 解析 `[InitVar]`：官方 JSON5 + `[值, "更新条件"]` 叶子、YAML 子集、`<initvar>`/代码块包裹、多条目深合并；按 MVU 官方源码处理对象 `$meta`、数组 `$arrayMeta`/魔法标记、`extensible`、`recursiveExtensible`、`required` 与 `template`，并在建表前清理所有保留元数据。
- 启用的注册 Schema 在隔离环境中使用实际 JavaScript 和 Zod 构造，支持计算属性、简写、函数与循环生成声明。转换器读取实际 Schema 对象建表；任意变换输出以完整 JSON 保留，原 Schema 在运行时校验与变换。环境依赖和无法映射的结构会报告或中止。
- 固定字段保留普通列，稳定字典可用行表，复杂子节点局部保存 JSON。可缺失、可空或开放的根保留完整 JSON，以区分缺失、`null` 和空容器。无法无损表示的脚本完整替换会明确失败并保留已有数据。 [布局与存在状态](docs/design/layout-planning.md)
- 列来源：`[MvuUpdate]` 结构声明 > 状态栏/脚本成员访问扫描 > initvar 实际字段。
- 中文组名/字段名 → **拼音标识符**（内嵌 pinyin-pro 字典，与插件内部一致），DDL 注释保留中文。
- `[MvuUpdate]` 中的数值 `range` → `CHECK`、可选值数组 `range`/枚举 → `CHECK IN`、`format`/`check` → note、`_强制更新提醒` → “每次回复必须维护”。所有范围/枚举/格式均来自卡片自身规则。
- `${露出|扩张}经验` 类模板键会展开绑定到每个真实列；同表列的约束完全相同时，提示词保留合并写法以避免重复，SQL 约束仍逐列生效。

### 数据桥（写入卡内 tavern_helper 脚本）

新生成的卡内桥仅向 MVU转数据库扩展登记模板、布局和接口需求。请保持扩展启用；尚未加载时会自动等待并提示，加载后自动连接。旧卡的退出接管协议继续兼容。

布局保存在转换卡内，主要读写逻辑由扩展提供，桥中的版本号不是自动迁移机制。升级扩展不会把旧聊天改成新布局；已识别的旧布局按原结构处理。只有需要使用新布局功能时，才需重新转换原卡并新建聊天。

- **开局自动建表（对应 MVU 的 init 时机 → 龙血玄黄·数据库 的初始化）**：转换时把模板以 base64
  写入世界书条目 `__ACU_TEMPLATE_DATA__`，不改动开场白（纯文字开场白也能用）。
  扩展在进入聊天/首条消息时，若按模板表名检测到缺表，就调用
  `initGameSession({ injectTemplate:true, loadPreset:false, templateData })` 建表并写入初始行；
  已有表格的聊天不会被重置。唯一的自动恢复例外是：聊天只有一个非用户首楼、运行时明确出现其他卡的表且当前卡缺表；此时尚无游玩数据，会用当前卡模板替换异卡 checkpoint。只要已有用户楼层就绝不自动覆盖。
  若卡的开场白脚本会切换/重写首楼（如“重塑仙缘”类开局流程）
  而打断插件初始化，会自动轮询重试（约 1 分钟内）直到建表成功。
- 保存角色卡时仍会顺带把模板存为插件“全局模板预设”，可在插件模板面板手动切换备用。

### MVU 更新规则 → 填表提示词
`[MvuUpdate]` 的规则会写入模板 note（即插件注入给填表 AI 的提示内容）：
`range` → CHECK 约束与【强制约束】、枚举 → CHECK IN、`format`/`check` → 【强制约束】、
`_强制更新提醒` → “每次回复必须维护”。填表 AI 会按这些规则决定何时增改删。
- `getAllVariables()` shim：数据库表格 → `stat_data` 嵌套形状（含 `[值,条件]` 还原、`display_data` 镜像）——**状态栏 HTML 不用改**。
- `Mvu.getMvuData / Mvu.replaceMvuData` 兼容层：旧脚本 diff 写库。
- 运行时解析 `<UpdateVariable>` / `<json_patch>` 块（`_.set/add/remove/assign`、JSON Patch）写库；开场同楼的 initvar 与更新块按 MVU 顺序合并为最终初始化快照。
- 兼容 MVU/VWD 在开局事件中保留的 `[当前值, 描述]` 变量叶子：建表时按转换布局精确取出当前值，不会把整个数组写入 TEXT/枚举列；普通数组字段不受影响。
- 转换前可选「将容器保存为完整 JSON」，把各顶层容器相关的子表并入 JSON 列。填表可以用 SQLite 按路径更新。 [使用与边界](docs/validation/2026-09-22-full-json-containers.md)
- 新转换支持单例表中已识别的文本/可空及数字/布尔 pair 动态说明：转换界面在提示词模板扩展 EJS 桥就绪、龙血玄黄·数据库版本支持隐藏列时自动接入。说明随数据保存，在实际填表请求时读取；支持补充初始空说明、清空、刷新和删楼回退。含模板标记的说明以可逆 JSON 字符串显示，避免再次执行。需要保持提示词模板扩展启用；旧转换卡需重新转换，范围和证据见[动态说明验收](docs/validation/2026-09-16-vwd-prompt.md)。
- **问候语 `<UpdateVariable>` 覆盖初始值**：MVU 允许额外问候语里的更新语句覆盖 `[InitVar]`；
  转换后由扩展按 MVU 顺序合并 initvar 与开场白更新块，再提交最终开局快照。
- **命令与显示兼容**：`_.set`（双参/三参 `old,new` 两种格式）、`_.assign`（对象合并/按键赋值）、
  `_.remove/unset/delete`、`_.add`（数值加法带精度处理、日期字符串按毫秒推进转 ISO）；
  `display_data` 在会话内保存 `旧->新(原因)` 镜像（与 MVU 的 display 字符串同格式）。
- 公开 MVU 更新事件链由兼容层接管；`COMMAND_PARSED` 监听器可改写或追加命令，`VARIABLE_UPDATE_ENDED` 携带更新前后的完整 `MvuData`。具体参数语义和边界见兼容清单。
- 普通表格 CRUD、自动填表以及删除楼层、切换 swipe、增改消息造成的历史变化，都会在数据库快照稳定后同步转换卡前端；兼容 MVU 更新事件、数据库更新事件、安全内联重读入口和明确刷新控件。
- 标准 TH 变量接口默认仍为聊天作用域；读取转换卡消息数据使用 `TavernHelper.getVariables({type:'message'})`。全局函数、命名空间及 iframe 绑定共用适配，详见[接口清单](docs/validation/2026-10-25-variable-api.md)。
- 消息状态栏若在加载窗口读过未就绪的合并变量，待同楼快照就绪后会通过助手原生接口自动刷新一次；这会再运行一次作者启动脚本，并有会话、楼层、swipe、正文、页面及次数保护。
- 对只在首次挂载时调用一次 `getVariables({type:'message'})` 的内联开场前端，转换器会等待数据库变量 shim 就绪后再启动，避免选项列表在异步建表窗口读空。

### 卡片清理
- `[InitVar]`、已迁移的静态结构声明和可明确识别的旧输出规则会从转换副本清理。分析旧更新条目时保留作者的自然语言业务要求和混合 EJS。可接入的 Schema 登记及作者业务脚本继续在相应时机运行。 [转换职责](docs/architecture.md)
- 正文请求会屏蔽主世界书中仅供填表的 `[M2SJK]` 条目及对应旧版 `[mvu_update]` 条目。`[mvu_plot]` 与双标记共享条目继续发给正文。数据库按自己的世界书选择读取填表内容。
- `[mvu_plot]` 剧情条目全部保留，内部 `{{get_message_variable::…}}` 宏改写为数据库表引用。
- EJS 的完整 `getvar('stat_data.组.字段')` 使用安全数据库路径读取；缺少任意中间组时返回 `undefined`，原有 `{ defaults: ... }` 继续生效。
- 保留原卡的剧情、独立状态展示和开场白，相关变量读取由兼容入口转接。需要人工核对的内容会列在转换报告里。
- **世界书独立**：内嵌世界书名称与外部世界书引用会追加 `_数据库` 后缀，避免导入转换卡时同名覆盖原卡世界书。

### EJS 条件重写

**EJS 整体保留，只改数据读取位置**：提示词先经 st-prompt-template 渲染 EJS、再由
数据库插件解析 `<if>`。因此世界书里的 EJS（`<% if %>`、`<%_ if %>`、else-if 链、
循环、函数调用、`<%- %>` 输出等）原样保留。`getvar/setvar`、`getMessageVar/setMessageVar`
等变量调用保持原文：原 EJS 执行器计算参数，扩展在实际模板上下文中将 `stat_data`
转接到数据库。普通变量与 `global/local/initial` 作用域继续调用宿主原接口；动态拼接、
数组路径、`defaults`、条件写入、返回值及合并选项不依赖逐卡表达式改写。
`variables["stat_" + "data"]` 同样读取数据库视图。缓存修改只在本次执行上下文可见，
不随其他字段的写入顺带持久化。

旧式 `getAllVariables().stat_data`、`allVariables().stat_data`、`all_variables.stat_data`、
`window.stat_data` / `globalThis.stat_data` 和 `TavernHelper.getVariables({type:'message'}).stat_data`
等直接读取仍通过兼容入口转接。扩展从卡内布局与实际表格惰性重建 `stat_data`，
不要求卡内桥先运行。仅在 EJS 条件中出现、不在 `[InitVar]` 中的字段也会补进列定义。

历史读取使用对应楼层结束时的状态。SQL 历史需要数据库发布包提供公开的 `exportTableSnapshotsAtMessages` 接口。缺少此接口时，旧宿主的备用读取仅覆盖可从完整快照和普通行操作重建的状态。消息或快照不可用时会报告读不到。 [历史接入验证](docs/validation/2026-10-13-message-history.md)
写入限当前 AI 消息的选中 swipe，任意历史写入、未选中 swipe 和夹带 `stat_data`
的原生批量写入明确拒绝。详见[接口范围](docs/validation/2026-10-08-variable-adapter.md)。
直接读取宿主消息对象或 MVU 私有状态的脚本可能读不到数据库字段。兼容层通过 MVU、酒馆助手和 EJS 的公开接口提供合并后的视图。

若 st-prompt-template 合并多个世界书条目时遇到跨条目的 `const/let/class x` 与
`if (typeof x === 'undefined') var x = ...;` 回退声明冲突，转换器会只隔离这一精确匹配的回退条目，并在转换报告中记录。

设置面板可选开启“安全的简单 EJS 条件翻译”：仅将无 `else`、无嵌套、静态字段与
字面量比较的简单 `<% if %>` 转为数据库 `<if db>`；复杂分支、循环和函数仍保留 EJS。
该选项默认关闭，兼容层仍是主路径。

初始数据中的 `<user>`、`{{user}}`、`<char>` 等宏会在进入当前聊天后调用
SillyTavern 原生 `substituteParams` 解析。表名中的宏不会运行时求值，而会静态规范化为稳定名称，
例如 `{{user}}表` 转为 `user表`、`{{getvar::阵营}}资料表` 转为 `getvar_阵营资料表`；卡内 MVU 逻辑路径保留原宏，进入聊天后再解析为当前用户/角色名。数据库始终读写 `user表`，状态栏则仍可按 `stat_data.{{user}}`（宏展开后的实际用户名）读取。
固定列名仍不支持运行时宏。
表格提示词中的 `{{getvar::...}}` 等只读宏也会在每次生成请求时解析；作用于
`WORLD_INFO` 的 promptOnly 静态查找正则会迁移到表格提示链，并保留原正则的运行时启用状态。

## 开发

维护资料、源码定位和验证入口见[文档索引](docs/README.md)。

```bash
node test/run-tests.js                    # 全量测试：默认只输出数量和汇总
node test/run-tests.js --grep "桥|扩展"  # 只跑相关用例
node test/run-tests.js --verbose          # 诊断时显示每条用例和完整桥日志
node build-extension.js  # 重新构建扩展文件
```

默认模式会抑制通过用例的 VM/数据桥日志；用例失败时自动回放最后 20 条截断日志。也可使用 `TEST_VERBOSE=1` 开启详细模式。
修改 `src/` 中的任意模块后都需要重新构建；浏览器安装入口为根目录 `index.js`。

真实酒馆验收单独运行 `node test/real-host.js`（Node 22 与本地上游依赖），使用公开合成卡及隔离数据目录。环境、场景和已知边界见[实机验收记录](docs/validation/2026-09-11-host.md)。
